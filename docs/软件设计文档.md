## 6. 配置结构（台账第 5 章）

配置文件：`configs/default.json`（出厂模板）→ 界面改动写 `configs/runtime.json`（优先加载）。**保存方式（v0.63）：在原配置文件基础上只更新本次改动的键**——服务端读 `runtime.json`（不存在时读启动加载的模板）→ 深合并本次 PUT 的键（取规范化后的值；AppConfig 不认识的键不写入；规范化后被删除的映射项同步删除）→ 校验 → 原子写回；文件里其它键、自定义键、键顺序与缩进原样保留；「启动数据源」/ 负荷辨识「套用到运行配置」等**未经保存的运行期改动不随后续保存落盘**；服务启动后在外部手改文件的内容不会被内存配置覆盖；`PUT /api/config` 响应新增 `config_file_updated` / `config_file`。两侧同一机制（分路侧写 `branch_runtime.json`）。总线侧数据源设置通过「数据源与控制」页的**「保存总线侧配置」**按钮落盘（数据源 + 量纲口径 + 列映射一起写）。加载优先级：`ELEC_TOOL_CONFIG`(整份 JSON) > `ELEC_TOOL_CONFIG_PATH` > `runtime.json`(存在时) > `default.json`。✅沙盒实录

## 9. 生产推荐流程（台账第 7 章）

**推荐拓扑（现场实时监测）** ✅架构实录 / 🔶现场未验证

```
采集装置(二次侧 6400Hz) ──写──> data/live.csv ──tail──> csv_tail 源 ──> LiveEngine ──WebSocket──> 浏览器(局域网)
                                                            │
                                                            └──> output/result_*.csv（定时导出/归档）
```

**推荐操作序列**

1. 部署：§2.2–2.5（离线机器走 §2.4(b)/(c)），5 条验证命令全绿；
2. 口径自检：`cli.py selftest --fs <现场fs> --freq <额定> --pt <PT> --ct <CT>` 必须 44/44；
3. 数据体检：`cli.py sources --file <现场数据>`，确认编码/列映射/推算采样率；
4. 离线对账：`cli.py compute --file <现场数据> --format csv --out output/对账.csv`，与现场表计/其它系统比 U、I、P、PF、THD（差异 >1% 要查变比与口径）；
5. 实时上线：`cli.py serve`（或 systemd/NSSM 常驻 + `ELEC_TOOL_AUTOSTART=1`），源切 `csv_tail`；
6. 窗长按业务设定：电能质量类建议 voltage/current/harmonic 用 1s~5s，趋势类可用 1s 步长滑动；
7. 归档：定时导出 CSV/JSON，保留 `notes` 与缺口日志作为数据质量证据。

## 3. KPI / 验收口径

### 3.1 指标数学定义（通用定义，非项目实测；✅ 数学事实）

| 指标 | 定义 | 特性与判据 |
| --- | --- | --- |
| MAE | `MAE = (1/n) · Σ|ŷᵢ − yᵢ|` | 与原数据同量纲；对异常值**不敏感**（线性惩罚）；直观可解释「平均偏多少 W」 |
| RMSE | `RMSE = sqrt( (1/n) · Σ(ŷᵢ − yᵢ)² )` | 同量纲；对大误差**平方放大**，故 RMSE ≥ MAE 恒成立；两者差距大 ⇒ 误差分布不均（存在尖峰/离群） |
| R² | `R² = 1 − SS_res / SS_tot`，`SS_res = Σ(yᵢ − ŷᵢ)²`，`SS_tot = Σ(yᵢ − ȳ)²` | 无量纲；**依赖测试集方差**，跨数据集/跨划分不可直接比较；可为负（劣于常数均值预测） |

- 常用派生判据：`RMSE / MAE` 比值离 1 越远，说明误差越集中在少数大偏差样本；NILM 场景常配合「零负荷段占比」判读（大量 0 值会人为压低 MAE）。
- ⚠️ 以上为**教科书口径**，项目实际是否剔除零负荷段、是否按设备聚合、是否用中位数替代均值，见 3.2。

## 设备画像与总线侧负荷辨识算法方案

# 基于设备侧周波录波构建设备画像，并在总线侧实现负荷辨识的算法方案

## 1. 目标与核心路线

已知目标设备在设备侧采集的、包含设备启停过程的实时三相电压和电流周波录波，利用带启停标签的数据构建设备画像；随后在总线侧实时录波中加载该画像，检测并识别目标设备的启动、停止事件，输出事件时间、方向、幅值和置信度。

推荐路线：

**设备侧画像构建 → 总线侧候选事件检测 → 事件特征提取 → 画像匹配 → 干扰判别 → 状态机确认 → 事件输出。**

重要限制：设备侧电流不等于总线侧电流增量。总线侧观测由多个负荷、线路和电网扰动共同决定。若缺少同步设备侧/总线侧校准数据，画像可以用于候选检测和相似性匹配，但不能保证准确恢复目标设备贡献幅值，也不能保证在特征相似的设备之间唯一辨识。

## 2. 输入数据与数据约定

### 2.1 周波定义

电网频率为 50 Hz 时，一个周波为：

\[
T_0=\frac{1}{50}=20\text{ ms}
\]

每个周波包含三相电压、电流采样序列：

\[
X_k=\{u_a,u_b,u_c,i_a,i_b,i_c\}_k
\]

每相波形含 \(N\) 个采样点。频率存在波动时，应根据时间戳、过零点或 PLL/相位跟踪确定周波边界，避免固定点数切片造成相位漂移。

### 2.2 必需元数据

建议保存设备 ID、测点 ID、采集时间戳、采样率、周波采样点数、相序、通道映射、CT/PT 变比、量程、单位、启停状态标签、数据质量标记和设备运行工况。设备侧与总线侧的特征定义、单位、相序及变比约定必须一致；时间同步误差也应计入匹配容差。

## 3. 设备画像构建

### 3.1 预处理与事件分段

1. 校验采样率、通道顺序、量程、极性和数据完整性。
2. 检查缺采样、削顶、异常尖峰、传感器饱和。
3. 定位周波边界，适度去噪但保留真实启动瞬态。
4. 根据标签切分 OFF、STARTING、ON、STOPPING。
5. 若标签只有启停前后状态，则用变化点检测辅助定位事件边界。

保留三类数据：事件前背景窗口、启动/停止动态过程、事件后稳定窗口。可先用事件前 10 个周波、事件后 50 个周波作为实验起点，但应按设备真实启动时长调整，不能视为通用固定值。

### 3.2 稳态特征

三相电压、电流有效值：

\[
U_p(k)=\sqrt{\frac{1}{N}\sum_{n=1}^{N}u_p^2(k,n)},\quad
I_p(k)=\sqrt{\frac{1}{N}\sum_{n=1}^{N}i_p^2(k,n)}
\]

其中 \(p\in\{a,b,c\}\)。

基波有功、无功和视在功率：

\[
P_p(k)=U_{p,1}(k)I_{p,1}(k)\cos\phi_p(k)
\]

\[
Q_p(k)=U_{p,1}(k)I_{p,1}(k)\sin\phi_p(k),\quad
S_p(k)=U_p(k)I_p(k)
\]

应统一使用基波功率或总波形功率的计算口径，避免设备侧和总线侧不一致。

| 特征类别 | 具体特征 | 作用 |
|---|---|---|
| 电压 | 三相 RMS、基波幅值、相间不平衡 | 识别电压扰动 |
| 电流 | 三相 RMS、基波幅值、峰值 | 描述负荷水平和相别分布 |
| 功率 | 有功、无功、视在功率、功率因数 | 描述负荷变化及电气性质 |
| 谐波 | 3、5、7、11、13 次谐波及谐波比 | 区分部分非线性负荷 |
| 相量 | 基波相角、正序/负序/零序分量 | 描述相间特性 |
| 波形形状 | 峰值因数、波形畸变率 | 描述非正弦电流 |
| 稳定性 | 均值、标准差、分位数 | 描述工况波动范围 |

谐波比：

\[
H_{p,h}(k)=\frac{I_{p,h}(k)}{I_{p,1}(k)+\epsilon}
\]

负序/正序电流比：

\[
K_{I,2}(k)=\frac{|I_2(k)|}{|I_1(k)|+\epsilon}
\]

\(\epsilon\) 为防止分母接近零的稳定项。低电流状态下，不应把不稳定的相对谐波比作为强判据。

### 3.3 启动与停止动态特征

以事件周波 \(k_0\) 为中心，截取事件前后窗口：

\[
\mathcal W=\{X_{k_0-L_-},\ldots,X_{k_0+L_+}\}
\]

对特征 \(f_j(k)\) 计算相对事件前稳定基线的变化：

\[
\Delta f_j(k)=f_j(k)-\tilde f_{j,\mathrm{pre}}
\]

启动画像建议包括启动电流峰值、峰值持续周波数、三相电流增量轨迹、有功/无功功率变化、基波相位和谐波变化、启动至稳定运行的持续时间、多阶段启动或软启动特征，以及启动后的稳定增量。

停止画像建议包括电流与功率回落轨迹、停止瞬间暂态、电流衰减时间，以及停机后是否仍有辅助电路耗电。

相对时间动态特征：

\[
\mathbf z_{\mathrm{on}}(\tau)=
[\Delta I_a,\Delta I_b,\Delta I_c,\Delta P,\Delta Q,\Delta H_5,\Delta H_7,\ldots]
\]

\[
\tau=\frac{k-k_0}{K_{\mathrm{event}}}
\]

\(K_{\mathrm{event}}\) 为所选事件窗口的周波数。时间归一化便于比较不同长度的事件，但应同时保留真实持续时间。

### 3.4 多次事件统计建模

应采集不同日期、负载水平、温度、生产工况和电压条件下的多次独立启停事件，避免仅用单次波形作为唯一模板。

对特征样本 \(\mathbf z^{(1)},\ldots,\mathbf z^{(M)}\)，计算中心和协方差：

\[
\boldsymbol\mu=\frac{1}{M}\sum_{m=1}^{M}\mathbf z^{(m)}
\]

\[
\boldsymbol\Sigma=\frac{1}{M-1}\sum_{m=1}^{M}
(\mathbf z^{(m)}-\boldsymbol\mu)(\mathbf z^{(m)}-\boldsymbol\mu)^\mathsf T
\]

小样本或高维相关特征时，采用协方差收缩、对角协方差或稳健估计。若设备存在不同运行模式，应分别建立轻载、重载、启动、停止和周期运行等子画像。

### 3.5 画像文件结构

推荐采用 JSON 元数据 + NPZ 数值数组，或等价的版本化模型包：

```text
device_profile/
└── device_A/
    ├── manifest.json
    ├── steady_features.npz
    ├── startup_templates.npz
    ├── shutdown_templates.npz
    ├── feature_statistics.npz
    └── calibration.json
```

- `manifest.json`：设备 ID、画像版本、采样率、周波长度、相序、CT/PT 变比、特征定义版本和训练数据范围。
- `steady_features.npz`：各工况的稳态特征中心、协方差和容差。
- `startup_templates.npz` / `shutdown_templates.npz`：动态模板、峰值分布和持续时间分布。
- `feature_statistics.npz`：标准化参数、特征相关性及有效性标记。
- `calibration.json`：总线侧校准参数、匹配权重、阈值及校准版本。

画像应具备版本号、完整性校验、加载失败保护和回滚能力。特征定义或单位版本不一致时应拒绝加载。

**单相 / 分相设备的相别（v0.99.30 工程实现）**：画像另需记录"本设备接在哪几相"`phases`（`A`/`B`/`C`/`AB`/`AC`/`BC`/`ABC`，缺省 `ABC`）。依据是：单相设备的另外两相只有 CT / 采样噪声，其 ΔI 的 σ 被绝对下限（0.02 A）托底，若仍参与马氏距离，总线侧那两相任何负荷投切都会让 D² 爆掉。工程上的落法是**特征定义不变**、只在匹配时把未接相的维度从 Σ 与维数分母中剔除（与 3P3W 无 B 相 CT 的 `skip` 同一套机制），因此旧画像（无 `phases` 字段）行为完全不变。相别可由提取侧按"某相 |ΔI| 均值 ≥ max(2 %×最大相, 3×离散度)"自动判定，也可人工指定。**候选台阶序列**（找事件起点用的那条曲线）也按所声明的相取（P 口径 Σp_ph、I 口径 √Σi_ph²），否则 I 口径下三相合成会把单相设备的台阶按其它两相的基流压扁（背景 50 A 时 A 相 +3 A 只涨 0.275 A、连候选都不生成）；**事件输出**的 ΔI 同样按所接相取（v0.99.31），而 ΔP/ΔQ 保持三相求和口径（单相设备的增量即其自身）。

## 4. 设备侧到总线侧的迁移问题

设备侧电流可表示为 \(i_{\mathrm{dev}}(t)\)，总线侧电流通常为多负荷叠加：

\[
i_{\mathrm{bus}}(t)=\sum_{m=1}^{M}i_m(t)+i_{\mathrm{noise}}(t)
\]

目标设备动作时：

\[
\Delta i_{\mathrm{bus}}(t)=
\Delta i_{\mathrm{target}}(t)+
\Delta i_{\mathrm{other}}(t)+
\Delta i_{\mathrm{disturbance}}(t)
\]

两侧测点的电压、线路/变压器阻抗、CT/PT 变比、相位参考和时间同步误差均可能造成差异。

因此维护两类画像：

1. **设备固有画像**：设备侧启动/停止动态、谐波比例、相间分布、稳态工况和持续时间。
2. **总线侧观测画像**：目标设备动作在总线测点可观察到的变化特征及其分布。

最可靠的做法是采集部分同步设备侧与总线侧启停事件，学习从设备固有特征到总线观测特征的映射，并使用独立事件验证。缺少同步校准数据时，画像可以做候选检测和相似性匹配，但幅值估计应标记为低可信或不可用。

## 5. 总线侧实时事件检测算法

### 5.1 逐周波特征与缓存

每收到一个完整周波，提取：

\[
\mathbf x_k=[\mathbf I_k,\mathbf P_k,\mathbf Q_k,\mathbf H_k,\mathbf V_k,\mathbf B_k]
\]

其中包括三相电流、功率、谐波、电压和三相不平衡等特征。保留原始波形环形缓存，以便候选事件出现后回溯前后波形。

### 5.2 稳健基线与阈值

在确认无事件的背景窗口内计算中位数基线：

\[
b_j(k)=\operatorname{median}\{x_j(k-W),\ldots,x_j(k-1)\}
\]

用中位绝对偏差估计噪声尺度：

\[
s_j(k)=1.4826\operatorname{MAD}(x_j)+\epsilon
\]

标准化偏差：

\[
r_j(k)=\frac{|x_j(k)-b_j(k)|}{s_j(k)}
\]

多个相关特征同时超过阈值，或高可信度特征发生明显突变时，触发候选事件。阈值应使用验证数据标定。

### 5.3 CUSUM 变化点检测

对标准化有符号特征 \(y_k\)：

\[
G_k^+=\max(0,G_{k-1}^++y_k-\nu)
\]

\[
G_k^-=\max(0,G_{k-1}^--y_k-\nu)
\]

统计量超过阈值时触发正向或负向变化候选。可对多个特征分别运行检测器，再融合证据。稳健阈值快速发现大变化，CUSUM 补充发现小而持续的变化；两者只产生候选，不直接判断目标设备身份。

### 5.4 候选事件前后差分

设候选事件周波为 \(k_0\)，事件前后窗口为 \(W_{\mathrm{pre}}\)、\(W_{\mathrm{post}}\)：

\[
\Delta\mathbf x=
\operatorname{median}(\mathbf x_{k_0:k_0+W_{\mathrm{post}}})
-\operatorname{median}(\mathbf x_{k_0-W_{\mathrm{pre}}:k_0-1})
\]

同时保留逐周波动态轨迹，避免仅用前后差值丢失启动峰值、衰减斜率和多阶段变化。特征包括三相电流增量、有功/无功增量、电压变化、谐波比例、相位变化、启动峰值、变化斜率和持续时间。

### 5.5 马氏距离统计匹配

对候选特征 \(\mathbf z\) 与画像中心 \(\boldsymbol\mu\) 计算：

\[
D^2(\mathbf z)=(\mathbf z-\boldsymbol\mu)^\mathsf T
\boldsymbol\Sigma^{-1}(\mathbf z-\boldsymbol\mu)
\]

距离越小，表示候选特征越接近画像中心。为提升稳定性，可采用：

\[
\boldsymbol\Sigma_\lambda=\boldsymbol\Sigma+\lambda\mathbf I
\]

启动和停止画像分别计算距离，并与验证集标定的阈值比较。

**未接相维度的处理**：设备只接部分相时，未接相的 ΔI 维度在 \(\boldsymbol\Sigma^{-1}\) 中不参与（等价于把这些维的权重置 0），维数 \(d\) 同步按参与维数计（置信度 \(e^{-D^2/2d}\) 的口径不变）。此外**候选事件的搜索序列也按相别取**——P 口径用所声明相的 \(\sum p_\phi\)，I 口径用 \(\sqrt{\sum i_\phi^2}\)：三相合成电流会让单相设备的台阶按其它两相基流被压扁（背景 50 A 时 3 A 的台阶只剩 0.275 A），低于候选门槛即**静默漏报**。

### 5.6 DTW 动态模板匹配

对候选动态序列与画像模板计算动态时间规整距离：

\[
D_{\mathrm{DTW}}=\frac{1}{|\pi|}
\sum_{(i,j)\in\pi}d(\mathbf z_i,\mathbf t_j)
\]

其中 \(\pi\) 是满足时间顺序约束的匹配路径，\(\mathbf t_j\) 是画像模板。DTW 可容忍有限的启动时长差异，但必须限制时间扭曲范围。

### 5.7 综合得分与拒识

\[
S=w_sS_{\mathrm{stat}}+w_dS_{\mathrm{DTW}}+
w_pS_{\mathrm{phase}}+w_vS_{\mathrm{voltage}}+
w_tS_{\mathrm{timing}}
\]

权重和阈值需通过独立验证事件标定。综合分数不天然等于概率；只有经独立验证集校准后，才可报告概率。

当电压扰动显著、其他负荷可能同时动作、数据质量差、启动/停止得分接近、当前工况不适用画像或设备特征相似时，应降低置信度或输出 `UNKNOWN`。

## 6. 事件状态机与确认

建议状态为：

1. `NORMAL`：稳定监测，安全更新背景统计量。
2. `CANDIDATE`：检测到变化，冻结事件前基线并保留事件缓存。
3. `PROFILE_MATCH`：分别匹配启动、停止画像。
4. `CONFIRM`：检查时序、幅值、持续时间、数据质量和干扰。
5. `OUTPUT`：输出已确认事件。
6. `REJECT/UNKNOWN`：拒绝候选或标记未知，恢复监测。

确认条件：
- 候选特征落在画像容差范围内；
- 最优模板与次优模板有足够区分度；
- 动态轨迹与稳态增量相互一致；
- 排除明显电压扰动和数据质量异常；
- 与近期已输出事件去重；
- 设备状态转移合理。

候选事件期间必须冻结背景基线，防止慢速启动被自适应基线吸收。设备状态也应约束后续事件：OFF 状态下启动更合理；设备已 ON 时再次触发启动模板，应检查工况切换或重复触发。

## 7. 幅值估计与输出格式

### 7.1 区分观测幅值和设备贡献幅值

总线侧有功功率变化：

\[
\Delta P_{\mathrm{bus}}=P_{\mathrm{after}}-P_{\mathrm{before}}
\]

但：

\[
\Delta P_{\mathrm{bus}}=
\Delta P_{\mathrm{target}}+
\Delta P_{\mathrm{other}}+
\Delta P_{\mathrm{disturbance}}
\]

因此应分别输出总线侧观测变化幅值，以及目标设备贡献幅值估计及其不确定性（仅在可辨识时）。

### 7.2 贡献估计

有同步现场校准数据时，可建立：

\[
\Delta\mathbf x_{\mathrm{bus}}\approx
\mathbf A\boldsymbol\theta+\boldsymbol\varepsilon
\]

其中 \(\mathbf A\) 为校准后的特征映射或候选负荷矩阵，\(\boldsymbol\theta\) 为负荷贡献系数，\(\boldsymbol\varepsilon\) 为残差。可用带正则化的最小二乘估计。

若只有单一总线测点、缺少同步校准数据且多个设备特征高度相似，目标设备贡献可能不可辨识。此时不应将总线总变化直接当作目标设备功率。

### 7.3 建议事件输出

```json
{
  "device_id": "device_A",
  "event_time": "采集时间戳",
  "direction": "START",
  "observed_delta_p": 0.0,
  "estimated_device_delta_p": null,
  "confidence": 0.0,
  "status": "confirmed",
  "quality_flags": [],
  "profile_version": "1.0"
}
```

这是字段示例，具体类型和时间格式需按项目接口规范确定。若幅值无法可靠估计，应将估计字段设为 null，而不是用总线变化量替代。

## 8. 算法伪代码

### 8.1 离线画像构建

```python
def build_device_profile(waveforms, state_labels, config):
    validate_waveforms(waveforms, config)
    segments = segment_by_state(waveforms, state_labels)
    features = extract_cycle_features(
        waveforms, config.feature_config
    )
    events = extract_transition_events(features, segments)

    profile = {
        "steady_modes": fit_steady_models(segments, features),
        "startup": fit_event_templates(events, "start"),
        "shutdown": fit_event_templates(events, "stop"),
        "feature_schema": config.feature_schema,
        "quality_stats": compute_quality_stats(features),
    }

    validate_profile(profile, events, config)
    return profile
```

以上为接口级伪代码，函数需结合实际录波格式实现。训练、验证、测试集应按完整启停事件、日期或工况划分，避免同一次事件的相邻周波泄漏到不同数据集。

### 8.2 总线侧在线辨识

```python
def identify_device(bus_cycle, profile, runtime_state):
    features = extract_cycle_features_online(bus_cycle)
    quality = assess_signal_quality(features)

    if not quality.valid:
        return {"status": "unknown",
                "reason": "poor_signal_quality"}

    candidate = detect_change_point(features, runtime_state)
    if candidate is None:
        update_background_if_safe(features, runtime_state)
        return None

    event_window = runtime_state.get_event_window(candidate)
    start_score = match_profile(event_window, profile, "startup")
    stop_score = match_profile(event_window, profile, "shutdown")

    decision = confirm_event(
        start_score, stop_score, event_window,
        quality, runtime_state
    )

    if decision.confirmed:
        runtime_state.update_device_state(decision.direction)
        runtime_state.record_event(decision)
        return {
            "device_id": profile["device_id"],
            "event_time": decision.event_time,
            "direction": decision.direction,
            "amplitude": decision.amplitude,
            "confidence": decision.confidence,
            "status": "confirmed",
        }

    return {"status": "unknown", "reason": decision.reason}
```

以上伪代码还需补充实际数据结构、缓存管理、超时策略、日志、异常处理、阈值配置和并发机制后才能用于生产部署。

## 9. 工商业复杂工况增强策略

| 现场问题 | 推荐处理 |
|---|---|
| 多设备同时启停 | 多事件检测、背景残差建模、多画像联合匹配 |
| 三相不平衡 | 逐相特征及正序/负序/零序分量 |
| 变频器、整流器等非线性负荷 | 基波、谐波、相位和动态轨迹联合匹配 |
| 电压波动或电网扰动 | 独立检测电压事件，降低受影响特征可信度 |
| 同设备多种工况 | 多模式画像及工况专属得分 |
| 两侧幅值不同 | 同步现场事件学习观测映射与容差 |
| 启停标签不完整 | 变化点检测辅助定位，再结合状态标签筛选 |
| 低信噪比、小幅事件 | 稳健统计、CUSUM、多周波证据和延迟确认 |
| 画像长期漂移 | 漂移监控、审核更新、版本管理与回滚 |

如果多个设备在总线侧的特征高度相似，单个测点可能无法唯一辨识。可增加测点、生产运行记录或其他独立信息；否则应输出候选设备及不确定性。

## 10. 验证与验收

### 阶段一：画像有效性
检查不同日期、负载水平和启停批次下的特征稳定性，以及启动与停止的可区分性。

### 阶段二：总线侧迁移
用设备侧画像测试不同电压、测点和背景负荷；尽可能采集同步设备侧与总线侧启停事件作为校准集。

### 阶段三：复杂工况压力测试
测试多个设备同时启停、变频调速、三相不平衡、电压扰动、低幅值事件和周期性负荷。

### 阶段四：实时部署
测试周波处理耗时、事件确认延迟、内存占用、长时间运行稳定性及画像切换安全性。

| 指标 | 定义 |
|---|---|
| 事件精确率 | 正确识别事件数 / 输出事件总数 |
| 事件召回率 | 正确识别事件数 / 实际事件总数 |
| F1 值 | 精确率与召回率的调和平均 |
| 误报率 | 单位时间误报次数或负样本事件误报比例 |
| 事件时间误差 | 检测时间与参考事件时间之差 |
| 启停方向准确率 | 正确判断启动/停止的事件占比 |
| 幅值误差 | 估计幅值与参考设备贡献幅值的差异 |
| 未知事件拒识率 | 对无法可靠辨识事件正确拒绝输出的比例 |
| 实时性 | 周波处理耗时及事件确认延迟分位数 |

测试集必须包括目标设备不动作、其他设备动作及电压扰动等负样本。50 Hz 下每周波为 20 ms，但不代表算法必须或必然在一个周波内完成确认；实际延迟需通过实测确定。

## 11. 工程实施路线

1. **基础版**：三相逐周波特征、稳健变化点检测、启动/停止画像、马氏距离匹配和状态机确认。
2. **增强版**：加入 DTW 动态模板、工况分类、电压扰动抑制和多设备联合匹配。
3. **现场自适应版**：利用同步设备侧/总线侧数据校准映射，开展漂移检测、阈值重标定和版本化更新。

优先验证三个基础问题：
- 设备侧画像是否具有足够区分性；
- 画像能否迁移到总线侧观测；
- 总线侧多设备同时变化时能否避免错误归因。

若没有总线侧同步校准样本，且目标设备与其他设备特征相似，应将系统设计为支持置信度、未知类别和拒识机制的辨识系统，而不是保证所有事件均可唯一识别的分类器。
