# 智能问答模块说明文档

## 1. 模块定位

“智能问答助手”是电气量计算与负荷辨识平台内的**调参辅助文档助手**。它在当前业务页面以固定侧栏呈现，左侧浏览产品文档、操作手册与参数清单，右侧提问、查看回答和引用。它优先帮助工程师 / 运维 / 交付人员查找平台参数、理解算法配置、设计可复现实验和排查回放结果。

本模块当前**提供实验指导，不直接执行实验**：它不会替用户运行终端命令、修改运行配置、启动 / 停止数据源或调用设备。助手没有连接具备授权与审计的实验执行 API；回答不得把建议步骤描述成“已替用户执行”。

## 2. 启动时的本地知识库

助手服务初始化时从仓库内的固定、已跟踪文件构建只读内置文档库；页面初始化时通过同源接口一次加载文档目录与全文，便于在侧栏浏览。内置资料也参与 builtin、local、cloud 三种问答通道的本地检索：

| 文档 | 内容来源 |
| --- | --- |
| 软件设计文档 | README 的系统定位 / 目录与配置 / 验证 / 生产流程章节、`REPORT.md` 稳定设计结论、设备画像算法方案 |
| 软件使用文档 | 完整 `README.md` 用户手册 |
| 软件部署说明文档 | README 快速开始、本地部署、Web 启动与生产流程章节 |
| 软件算法调参与验证文档 | 完整 `NILM_TUNING_GUIDE.md` |
| 平台参数清单 | 由 `AppConfig` 代码默认值、`configs/default.json`（总线侧模板）与 `configs/branch.json`（分路侧模板）合并路径生成；三类来源独立成列，并对每侧缺少的字段标注未显式配置 |
| NILM 数据定义与质量说明 | `NILM_DATA_DICT.md` |
| 智能问答模块说明文档 | 本文件 |

参数清单分别展示**代码默认值、总线模板值、分路模板值**，都不是用户当前有效值。运行时配置文件、环境变量、页面热更新、命令行覆盖和两侧各自的配置加载规则都可能改变实际值；模板列若显示“未显式配置”，不能据此推断最终值。参数解释优先结合调参手册、README 配置章节及代码校验规则。

内置知识只读取上述明确列出的项目文档与模板，不读取 `tmp/`、用户真实数据、助手管理员上传目录或运行产物。修改这些文档后需重启服务，重新构建内置语料；用户导入的附加文档仍由管理员单独维护。

## 3. 如何使用

1. 在允许显示入口的业务页点击“智能问答助手”，同一页面右侧固定打开侧栏；无需跳转独立页面。
2. 在“文档”区搜索并选择软件设计、使用、部署、调参验证、参数清单、数据字典或本模块说明。选中后可在侧栏阅读完整 Markdown 文档。
3. 在“问答”区提问。建议写明当前业务页、总线侧 / 分路侧、数据源、接线方式、PT/CT、检测量和希望验证的现象；参数问题优先从平台参数清单检索，并结合完整说明文档回答。
4. 需要实验建议时，明确目标事件 / 设备、已有真实数据、当前参数和判定标准。要求助手给出“前置条件 → 单变量改动 → 操作命令或页面路径 → 预期现象 → 记录项 → 通过 / 失败判据 → 回滚方式”。
5. 对回答中的参数或命令，以引用文档和当前运行配置交叉核对；不要把出厂默认值误当成运行期实际值。

会话仅保存在当前页面内存；刷新页面后会清除。文档侧栏是只读浏览器，不会改变业务配置。

## 4. 问答通道与数据边界

- **内置知识库（builtin）**：默认且零模型依赖。仅在应用服务器本机检索内置与管理员导入的文档，返回相关摘录和引用；不调用本地或云端大模型。它不是生成式回答，未检索到资料时会明确提示。
- **本地模型（local）**：由应用服务把问题、必要的对话历史和检索片段发送到所配置的本机 / 内网 OpenAI-compatible 接口。本地请求不经系统 HTTP 代理。
- **云端模型（cloud）**：会把问题、对话历史和命中的检索片段发送给所配置的云端服务。发送前会检查明显密钥模式和管理员敏感词；该检查不是完整 DLP，不能保证识别所有个人信息或业务秘密。未经授权的数据不要发往云端。
- **管理员附加文档**：文本文件由管理员显式导入，保存在本地助手数据目录；它们与程序内置资料分开管理。清空操作只影响管理员导入的资料，不会删除随程序加载的内置文档。
- **引用名脱敏**：当前服务端沿用既有 `branch.hide_ui` 作为来源名称脱敏判据，这是暂定映射（该字段原义为隐藏分路侧界面，并非助手专属开关）。若该配置为真，问答响应中的引用名称和答案文本会脱敏；不要把客户端传入值当成安全控制。

## 5. 调参实验回答规范

调参建议应尽可能可复现、可逆、可判读：

1. **先确认口径**：两侧 / 接线 / PT、CT / P 或 I / 时间戳与采样率 / 原始文件范围；未知项标记为待确认。
2. **建立基线**：保留原配置，记录配置文件来源、软件版本、数据文件摘要、数据时间范围、事件真值与现有输出。
3. **单变量实验**：一次只修改一个主要参数；解释参数作用、方向预期、适用边界和可能副作用。涉及多个互相制约的参数时，说明分组顺序和回退点。
4. **给出可执行方案**：列出页面路径或完整命令、输入文件、输出目录、预期字段 / 事件数量和需要保存的日志；命令必须来自项目现有帮助文档或代码，不得编造。
5. **写清判据**：用已知真值对账，分别报告命中、漏报、误报、时间偏差、幅值 / 置信度与失败原因；经验阈值标成经验值，不能承诺必然效果。
6. **保护现场状态**：提醒先备份配置与实验输入；没有执行工具时只提供操作步骤。用户完成实验并回报真实结果后，再基于实录分析下一步。

## 6. 管理员配置与维护

管理员可在面板设置中选择 builtin / local / cloud、维护模型地址与参数、启用 RAG、导入附加文本知识、配置敏感词和控制入口可见页面。配置与附加知识写操作受服务端 `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN` 保护；API Key 不会经公开配置接口回传。可持久化使用的密钥应通过服务端环境变量设置，避免仅在进程内存中的 UI 临时值。

`visible_views` 只控制前端入口在哪些业务页显示，不是用户身份认证或账户权限。向不可信网络开放服务前，必须由部署方配置 HTTPS / 网络访问控制并保护管理员口令。

## 7. 主要接口与验证

- `GET /api/assistant/documents`：获取内置文档元数据与全文，供同页文档栏初始化。
- `GET /api/assistant/config`：读取不含密钥正文和敏感词正文的公开设置。
- `GET /api/assistant/knowledge`、`POST /api/assistant/knowledge/import`：查看 / 导入管理员附加知识。
- `POST /api/assistant/chat`：builtin、local 或 cloud 问答；支持 JSON 与 SSE 流式响应。
- 回归入口：`tests/test_assistant.py`、`tests/test_server.py`、`tests/test_web_ui.py`、`node tools/ui_assistant_check.cjs`。
