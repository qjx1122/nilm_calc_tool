# 智能问答模块说明文档

## 1. 模块定位

“智能问答助手”是电气量计算与负荷辨识平台内的**调参辅助文档助手**。它在当前业务页面以固定侧栏呈现：左侧固定宽度且可收起的会话管理栏，标题为“智能问答助手”；右侧为自适应问答区，桌面端可从标题栏收起 / 恢复左栏，窄屏默认收起为抽屉、按需展开。右下角悬浮入口支持鼠标 / 触屏拖动，可移到当前视口内任意位置；拖动位置仅在当前页面运行期间保留。助手打开时悬浮入口隐藏；助手关闭后恢复（若设置或会话抽屉等更深层覆盖区域仍打开，Escape 会先关闭该区域）。右侧仅在当前会话已有有效回答 / 操作提案时显示会话名；新会话或清空上下文后无标题。问答区底部保留逐会话“问答后端”下拉（本地模型 / 云端模型 / 内置知识库）；管理员设置中的默认后端仅用于默认 / 新建会话，用户可在 composer 中切换当前会话。切换已有消息的会话后端会经用户确认新建独立会话，旧会话及其路由保持不变。local / cloud 会话在发送按钮左侧显示对应具体模型下拉（保留无障碍名称，不显示可见标题），builtin 会话隐藏模型选择。local 候选由共享的已保存本地服务地址发现；cloud 候选仅来自已配置的默认模型 / 命名档案。本地模型名称不再是管理员设置项。底部附件按钮文案为“附件”，相关控件按视口宽度整齐排列并在窄屏自动换行；文档浏览、平台参数清单与凭据配置仍位于“配置与附加知识库”区域。助手优先帮助工程师 / 运维 / 交付人员查找平台参数、理解算法配置、设计可复现实验、分析波形截图和排查回放结果。

问答本身仍以指导为主；另有可选的**确认式受控业务工具**：自然语言只会触发预览卡，不直接执行。用户需检查工具名、参数、影响和侧别，明确点击确认后，服务端再次验证操作员令牌、scope、配置开关、提案有效期与侧别，再调用固定注册的业务 API。助手不会运行 shell、SQL、任意 URL 或模型提供的文件路径，也不会把“待确认”描述成“已执行”。未配置操作员令牌 / scope 或管理员关闭工具时，操作只能拒绝执行。

## 2. 启动时的本地知识库

助手服务初始化时从仓库内的固定、已跟踪 Markdown 文件构建只读内置文档库；页面初始化时通过同源接口一次加载文档目录与全文，便于在侧栏浏览。内置资料也参与 builtin、local、cloud 三种问答通道的本地检索。四份项目手册现以可追踪的独立文件交付：修改上游资料后，在仓库根目录运行 `python tools/generate_assistant_docs.py` 重新生成；运行 `python tools/generate_assistant_docs.py --check` 可检查是否过期。助手服务在启动时读取这些 Markdown，重新生成后需重启服务才会加载新内容。

| 文档 | 知识库文件与来源 |
| --- | --- |
| 软件设计文档 | `docs/软件设计文档.md`；由 README 架构 / 配置 / 验证章节、`REPORT.md` 稳定设计结论和设备画像算法方案生成 |
| 软件使用文档 | `docs/软件使用文档.md`；以完整 `README.md` 用户手册生成 |
| 软件部署说明文档 | `docs/软件部署说明文档.md`；由 README 快速开始、安装部署、Web 启动与生产流程章节生成 |
| 软件算法调参与验证文档 | `docs/软件算法调参与验证文档.md`；以完整 `NILM_TUNING_GUIDE.md` 生成 |
| 平台参数清单 | 服务启动时由 `AppConfig` 代码默认值、`configs/default.json`（总线侧模板）与 `configs/branch.json`（分路侧模板）动态生成；三类来源独立成列，并对每侧缺少的字段标注未显式配置 |
| NILM 数据定义与质量说明 | `NILM_DATA_DICT.md` |
| 智能问答模块说明文档 | `docs/智能问答助手说明.md`（本文件，人工维护） |

参数清单分别展示**代码默认值、总线模板值、分路模板值**，都不是用户当前有效值。运行时配置文件、环境变量、页面热更新、命令行覆盖和两侧各自的配置加载规则都可能改变实际值；模板列若显示“未显式配置”，不能据此推断最终值。参数解释优先结合调参手册、README 配置章节及代码校验规则。

文档生成器只读取明确列出的已跟踪项目文档与配置模板，不读取 `tmp/`、用户真实数据、助手管理员上传目录或运行产物。静态项目手册缺失时，服务仍可从这些正式源文件回退拼装；日常知识库使用生成的 Markdown 文件。用户导入的附加文档与内置语料分开管理。

## 3. 如何使用

1. 在允许显示入口的业务页可用鼠标 / 触屏拖动“智能问答助手”悬浮球，将其移到当前视口内任意位置；位置只保留到当前页面刷新 / 关闭。点击悬浮球后，同一页面右侧固定打开侧栏，无需跳转独立页面。打开后悬浮入口隐藏；点击关闭，或在没有更深层覆盖区域时按 Escape 关闭助手后，入口才按助手启用状态与当前页面可见权限恢复。桌面端默认显示左侧会话栏，可点问答标题栏的“收起会话”隐藏左栏、让问答区占满宽度，再点“显示会话”恢复双栏；窄屏默认收起会话栏，点“显示会话”以覆盖式抽屉打开，再点“收起会话”关闭。按钮会同步可访问名称与展开状态。若窗口高度不足以同时显示界面，助手外层会出现纵向滚动条；消息、会话列表和设置仍可分别内部滚动，滚到内层边界后滚轮会继续滚动外层。
2. 左侧会话面板标题为“智能问答助手”；标题下可新建会话、搜索标题。默认按当前列表顺序将前 5 条显示为“最近会话”，其余显示为“历史会话”。条目展示标题与时间；单击切换，拖拽排序，右键或“⋯”菜单可重命名、清空上下文或删除。长标题会省略显示。右侧问答区在已有有效回答 / 操作提案后显示当前会话名；新会话或清空上下文时不显示标题。
3. 问答区底部可为当前会话选择本地模型、云端模型或内置知识库；若已有消息，切换后端会确认并新建独立会话，旧会话不改路由。管理员设置中的“默认后端”仅用于默认 / 新建会话。local 下拉只显示已保存本地服务地址发现的模型，可用管理员口令刷新；云端下拉只列已配置的默认模型与命名档案；builtin 隐藏模型选择。管理员设置不保存 local 模型名称。local / cloud 会话的具体模型选择也会按会话隔离；正文区区分用户与助手消息并滚动显示，Markdown 支持表格、代码、列表和公式。输入框 Enter 发送、Shift+Enter 换行。
4. 需要查看完整本地帮助文档或平台参数清单，点击输入区旁的“配置与附加知识库”，再展开“浏览本地帮助文档与完整平台参数清单”。设置内容由 overlay 内普通 `div.assistant-settings-scroll` 承载；该滚动区绝对定位并用 `inset:0` 明确约束可用高度，设置 `overflow-y:scroll` 和高对比滚动条，不依赖 `<details>` 本身或内容体计算滚动高度。文档目录 / 正文仍优先在各自内层滚动，到边界后 wheel handler 将滚轮交给设置滚动区。该区可用 Tab 聚焦，设置标题 sticky，关闭按钮可达。目标浏览器和系统可能使用会自动淡出的 overlay scrollbar；需在目标环境实际确认滚动条视觉效果，本说明不替代现场验收。在这里可配置默认问答后端、模型接口、管理员附加知识和凭据；管理员口令与操作员令牌相互独立。操作员令牌填入后点击“验证操作权限”，请求操作后检查预览卡的工具、参数、影响、侧别和有效期；高风险操作还要输入二次确认码并再次确认。
5. 可在输入框粘贴、拖放或通过“附件”按钮选择 PNG / JPEG / WebP 波形截图（单张 ≤3 MiB，每轮最多 3 张、总计 ≤5 MiB）。builtin 是文本检索通道，不解析图片；需在默认后端设置中选择支持视觉输入的 local / cloud 模型后才能分析。local 图片发送到配置的本机 / 内网服务；cloud 每次发送附图前会再次确认。不要上传涉密 / 个人数据。
6. 提问建议写明当前业务页、总线侧 / 分路侧、数据源、接线方式、PT/CT、检测量和希望验证的现象。参数问题优先检索平台参数清单；实验建议要求说明前置条件、单变量改动、页面路径 / 现有命令、预期现象、记录项、通过 / 失败判据与回滚方式。遇到超时可检查模型服务和设置区中的超时参数。
7. 对回答中的参数或命令，以引用文档和当前运行配置交叉核对；不要把出厂默认值误当成运行期实际值。若需要的是未注册工具、任意文件操作或“清除缓存”，助手会拒绝，不会猜测替代动作。

会话及截图只保存在当前页面内存，刷新后清除；不实现跨刷新历史持久化。文档浏览区为只读，不会改变业务配置。

## 4. 问答通道与数据边界

- **内置知识库（builtin）**：默认且零模型依赖。仅在应用服务器本机检索内置与管理员导入的文档，返回相关摘录和引用；不调用本地或云端大模型，也不做视觉分析。未检索到资料时会明确提示。
- **本地模型（local）**：由应用服务把问题、必要的对话历史、检索片段及用户主动附加的截图发送到管理员配置的本机 / 内网 OpenAI-compatible 接口。本地请求不经系统 HTTP 代理；模型须支持视觉输入才会分析截图。用户可在 composer 底部逐会话选择 local；模型候选从服务端发现缓存读取（先请求已保存 endpoint 的 `/models`，必要时回退 Ollama `/api/tags`），管理员可用设置内的刷新按钮更新缓存。发现和聊天共用同一份已保存 `local_base_url` 与 API Key，刷新端点不接受请求体 endpoint；管理员设置不再包含 local 模型名称，问答前端不提供手工输入模型名的控件。前端只能从发现候选中选择并提交模型 ID；服务端仍固定使用管理员配置的本地 endpoint。builtin 会话隐藏具体模型选择。
- **云端模型（cloud）**：会把问题、对话历史和命中的检索片段发送给服务端按档案 ID 查找到的云端服务；客户端不能提交 endpoint 或 API Key。composer 中的 cloud 模型选择只列旧版 `cloud_base_url` / `cloud_model` / `cloud_api_key` 默认配置及管理员已保存的命名档案；旧默认字段继续兼容，管理员可另行添加最多 10 个档案，每档对应一个 HTTPS OpenAI-compatible endpoint、模型 ID 与 API Key。服务端对文字会检查明显密钥模式、管理员敏感词和常见本地文件 / 录波路径及文件名；这是保守的规则拦截，不是完整 DLP。用户附加的截图会以图像数据发送，但不经过文本敏感词扫描；浏览器每次云端发图前会再次确认。云端服务可能接收并处理图片，请勿上传涉密 / 个人信息；确认提示不代表图像已获得自动安全检测。
- **工具执行边界**：云端工具提议默认关闭（`cloud_tools_enabled=false`），须管理员显式单独打开，并且每个操作员仍需持有工具对应 scope；确认时服务端重新授权。操作员令牌是可选的：无效或已撤销的令牌只会禁用工具能力，不会阻断只读问答；身份端点仍拒绝无效令牌。工具执行结果只回到页面，不会追加发送给云端模型。
- **管理员附加文档**：文本文件由管理员显式导入，保存在本地助手数据目录；它们与程序内置资料分开管理。清空操作只影响管理员导入的资料，不会删除随程序加载的内置文档。
- **截图边界**：前端仅接受 PNG / JPEG / WebP，单张不超过 3 MiB、最多 3 张且每轮合计不超过 5 MiB；服务端再校验 Base64、MIME 与文件签名，并把问答请求体限制在 7 MiB。截图只为本轮模型请求留在内存中，不写入助手知识库 / 持久目录；会话和截图的浏览器副本刷新后清空。请只发送有权使用且确实需要分析的截图。
- **引用名脱敏**：当前服务端沿用既有 `branch.hide_ui` 作为来源名称脱敏判据，这是暂定映射（该字段原义为隐藏分路侧界面，并非助手专属开关）。若该配置为真，问答响应中的引用名称和答案文本会脱敏；不要把客户端传入值当成安全控制。

## 5. 调参实验回答规范

调参建议应尽可能可复现、可逆、可判读：

1. **先确认口径**：两侧 / 接线 / PT、CT / P 或 I / 时间戳与采样率 / 原始文件范围；未知项标记为待确认。
2. **建立基线**：保留原配置，记录配置文件来源、软件版本、数据文件摘要、数据时间范围、事件真值与现有输出。
3. **单变量实验**：一次只修改一个主要参数；解释参数作用、方向预期、适用边界和可能副作用。涉及多个互相制约的参数时，说明分组顺序和回退点。
4. **给出可执行方案**：列出页面路径或完整命令、输入文件、输出目录、预期字段 / 事件数量和需要保存的日志；命令必须来自项目现有帮助文档或代码，不得编造。
5. **写清判据**：用已知真值对账，分别报告命中、漏报、误报、时间偏差、幅值 / 置信度与失败原因；经验阈值标成经验值，不能承诺必然效果。
6. **保护现场状态**：提醒先备份配置与实验输入；没有执行工具时只提供操作步骤。用户完成实验并回报真实结果后，再基于实录分析下一步。

## 6. 管理员配置与维护

管理员点击输入区旁的“配置与附加知识库”后，可在同一面板内浏览完整本地文档 / 参数清单、选择 builtin / local / cloud、维护模型地址与参数、启用 RAG、导入附加文本知识、配置敏感词和控制入口可见页面。云端设置保留一组兼容旧版的默认 endpoint / 模型 / Key，并支持动态添加、编辑和删除最多 10 个命名 API 档案；档案元数据写入服务端普通配置，档案 API Key 只在服务进程内存中保存，重启后需重新输入，且不会经公开配置接口回传。档案写操作受管理员口令保护。管理员口令与操作员令牌也集中在此区域，但两者独立：管理员口令保护配置与知识写操作；操作员令牌验证身份及每工具 scope。若需重启后自动加载默认云端或本地密钥，应使用服务端环境变量。

受控工具设置包含全局 `tools_enabled`、工具 allow-list `enabled_tools`、独立 `cloud_tools_enabled` 和 `tool_audit_enabled`。新安装默认 `tools_enabled=false`、`cloud_tools_enabled=false`、审计开启。管理员 API 会拒绝非列表或含未注册名称的工具 allow-list；读取旧配置时若 `enabled_tools` 类型损坏，服务端回退为空 allow-list，fail-closed，不会自动启用全部工具。操作员凭证仅从服务端环境变量 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` 读取，格式为 JSON 数组，例如：

```json
[
  {"id":"field-operator-1","token":"请替换为随机生成的至少 16 字符令牌","scopes":["config.wiring.write","engine.start"]}
]
```

令牌只返回操作员 ID 与 scope，不会回显凭证；scope 只接受下表列出的精确值。至少使用随机高熵令牌，并通过部署环境的 secret 管理功能注入；不要将真实令牌写入仓库、配置文件或浏览器持久存储。该方案没有用户账号 / SSO，审计身份是令牌配置的 operator ID，不等价于强实名认证。


### 6.1 实施工程师：把令牌配置到实际服务进程

先区分两类凭证，必须使用不同的随机值：

- `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN`：服务级管理员口令，用于保存助手设置、管理附加知识和审计。仅在浏览器设置框里填写，不会替服务进程设置环境变量；需要在**实际启动服务的进程环境**中设置并重启。
- `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS`：操作员凭证 JSON 数组，用来控制谁能调用哪些工具。每个操作员应有独立的 `id`、随机 `token` 和最小 `scopes`。管理员口令本身不授予工具执行权限。

#### Linux / macOS：当前终端启动

在仓库根目录执行。示例只授予“列出录波文件 / 列出画像”的只读权限；命令会在本机生成两串随机值并在终端显示，保存到部署方的密码管理器，不要把输出贴到聊天、工单或 Git 仓库。

```bash
# 若旧服务正在运行，先在其终端按 Ctrl+C 停止
ADMIN_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
OPERATOR_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export ELEC_TOOL_ASSISTANT_ADMIN_TOKEN="$ADMIN_TOKEN"
export ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS="$(
  OPERATOR_TOKEN="$OPERATOR_TOKEN" .venv/bin/python -c \
  'import json, os; print(json.dumps([{"id":"field-readonly-1","token":os.environ["OPERATOR_TOKEN"],"scopes":["recordings.read","profiles.read"]}]))'
)"
printf '管理员口令：%s\n操作员令牌：%s\n' "$ADMIN_TOKEN" "$OPERATOR_TOKEN"
unset ADMIN_TOKEN OPERATOR_TOKEN
# 只在本机访问可用 --host 127.0.0.1；供受信内网访问时按网络策略配置监听地址
.venv/bin/python cli.py serve --host 127.0.0.1 --port 8000
```

#### Windows PowerShell：当前终端启动

```powershell
# 仅用于当前终端直接启动服务；每运行一次都会生成新值，不要在普通服务重启时重新生成
# 若旧服务正在运行，先停止它
$admin = (& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))").Trim()
$operator = (& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))").Trim()
$env:ELEC_TOOL_ASSISTANT_ADMIN_TOKEN = $admin
$env:OPERATOR_TOKEN = $operator
$env:ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS = (& .\.venv\Scripts\python.exe -c "import json,os; print(json.dumps([{'id':'field-readonly-1','token':os.environ['OPERATOR_TOKEN'],'scopes':['recordings.read','profiles.read']}]))").Trim()
Remove-Item Env:OPERATOR_TOKEN
# 可选：只显示 ID、长度与 scope，不显示 JSON 中的实际令牌
$rows = $env:ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS | ConvertFrom-Json
$rows | Select-Object id, @{Name='TokenLength';Expression={$_.token.Length}}, @{Name='Scopes';Expression={($_.scopes -join ',')}}
# 以下输出包含秘密值；仅在私密终端查看，并安全保存，勿录屏或写入日志
Write-Host "管理员口令：$admin"
Write-Host "操作员令牌：$operator"
& .\.venv\Scripts\python.exe cli.py serve --host 127.0.0.1 --port 8000
```

`export` / PowerShell `$env:` 只影响当前终端及它启动的进程。上述示例只适用于服务由**同一个终端直接启动**的情况。服务已由 systemd、Docker、NSSM、任务计划程序或 IDE 管理时，必须把变量配置到**相应服务 / 容器的运行环境或 secret 管理器**，然后重启该服务；在另一个终端设置变量不会改变已运行进程。示例每次运行都会生成一组新值；常驻服务应只生成一次并安全保存，轮换时同步更新服务环境与操作员令牌，再重启。不要假设项目会自动读取仓库里的 `.env` 文件。

PowerShell 的调用运算符是 `&`。若从网页 / 富文本复制后命令中实际出现字面 `&amp;`，应改为单个 `&`（HTML 转义文本不能直接作为 PowerShell 运算符）。执行 `Remove-Item Env:OPERATOR_TOKEN` 只删除用于临时构造 JSON 的辅助变量；操作员令牌已写入 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS`，不会被这条命令移除。

#### systemd 持久配置示例

把真实值写入受保护的环境文件，而不是 unit 文件或 Git 跟踪文件：

```text
# /etc/elec-tool/assistant.env；目录建议 0700，文件建议 0600
ELEC_TOOL_ASSISTANT_ADMIN_TOKEN='替换为随机管理员口令'
ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS='[{"id":"field-readonly-1","token":"替换为另一串随机操作员令牌","scopes":["recordings.read","profiles.read"]}]'
```

在服务 unit 的 `[Service]` 段加入：

```ini
EnvironmentFile=/etc/elec-tool/assistant.env
```

然后按实际 unit 名称重新加载并重启，例如：

```bash
sudo systemctl daemon-reload
sudo systemctl restart elec-tool
```

若使用 Docker / Windows 服务，应以相同原则通过部署 secret 或受权限保护的服务环境配置注入变量，并重启 / 重建服务。`ELEC_TOOL_ASSISTANT_ADMIN_TOKEN` 或操作员令牌列表有变更时，都要重启实际应用进程才能读取新值。文档自身改动也需重启助手服务，内置文档库才会重新加载。

服务运行后可从服务主机查询公开配置中的布尔字段，检查它是否加载了至少一条格式有效的操作员记录（端口按现场修改）：

```powershell
(Invoke-RestMethod 'http://127.0.0.1:8000/api/assistant/config').operator_tokens_configured
```

`false` 表示没有有效记录进入该服务进程；`true` 只证明至少有一条格式有效记录，不证明 UI 输入的令牌与它相同。该接口不会返回令牌值。

### 6.2 交付工程师：在管理面板开启受控工具

1. 服务重启后打开「模型配置与附加知识（管理员）」。管理员状态应由“尚未启用”变为“服务端管理员口令已启用”；在「管理员口令」框输入 `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN` 的值。
2. 展开「受控业务工具与审计」，勾选 **「启用受控工具」**，并在工具列表中只选择交付范围内需要的工具（全局 allow-list）。
3. 保持 **「记录指令与执行审计」**开启。审计文件位于助手数据目录 `tool_audit.jsonl`；应按现场安全要求备份和保护。
4. 初次部署建议只用本地、支持 OpenAI-compatible 工具调用的模型，并保持 **「允许云端模型提出工具操作」**关闭。`builtin` 仅做本地文档检索，不会调用大模型工具。云端模型若被选用，会将问题、对话历史及命中的知识片段发送到所配置的云端；云端工具开关必须另外显式开启。
5. 点击「保存设置」。管理面板的总开关、allow-list 和云端开关保存后更新运行配置；它们不会替代操作员令牌与 scope 校验。

开启工具的有效条件是：`tools_enabled=true`、对应工具在 `enabled_tools` allow-list 内、操作员令牌有该工具的精确 scope；云端模式还要求 `cloud_tools_enabled=true`。任何一项缺失都会导致工具不可用。新安装的总开关与云端工具开关都默认关闭。

#### 全局工具复选框与操作员 `scopes` 的配对

配置面板中每个工具复选框下方会显示「所需 scope：`<scope 值>`」。该值来自服务端固定工具目录（`GET /api/assistant/config` 的 `tools[].scope`），是一项工具的**单个必需 scope**，不是由管理员在此面板编辑的权限字段。复选框只把工具 ID 加入 / 移出全局 `enabled_tools` allow-list；不要把 scope 字符串填进 `enabled_tools`。

要让某个操作员实际使用已全局允许的工具，还必须把界面显示的**完全相同、区分点号且不带引号内容的纯文本**加入其 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` JSON 记录的 `scopes` 数组。scope 只在服务端环境配置中分配；此管理面板没有逐操作员 scope 编辑器。环境变量变更后必须重启实际服务，再用该操作员令牌重新验证。配置示例如下（令牌仅为占位符）：

| 现场需要开放的能力 | 管理面板勾选的工具 ID | 操作员 `scopes` 数组必须包含 |
| --- | --- | --- |
| 仅启动当前侧数据源 | `start_current_source` | `engine.start` |
| 只读查询录波与画像目录 | `list_recordings`、`list_profiles` | `recordings.read`、`profiles.read` |
| 同时开放上述三项 | `start_current_source`、`list_recordings`、`list_profiles` | `engine.start`、`recordings.read`、`profiles.read` |

例如，若管理员只勾选 `start_current_source`，操作员记录中的最小 scope 可为 `"scopes":["engine.start"]`；若还勾选两个目录查询工具，则对应记录要包含上述三个 scope。**全局 allow-list 保存的是工具 ID，操作员 JSON 保存的是 scope 值，二者不可互换。**同一 scope 若被多个工具共享，授予它会使该操作员具备这些工具的 scope 能力；它们仍各自必须在全局 allow-list 内。完整逐工具映射见 §6.6。

### 6.3 交付与实施：分配操作员令牌和最小 scope

`ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` 必须是 JSON **数组**，而不是单个对象。下面是只读示例；把 `token` 替换为本机安全生成的随机字符串：

```json
[
  {
    "id": "field-readonly-1",
    "token": "替换为至少 16 字符的随机令牌",
    "scopes": ["recordings.read", "profiles.read"]
  }
]
```

当前实现接受 `id` 由 1–64 位字母、数字、点、下划线或连字符组成；操作员 `token` 长度为 16–512 字符。scope 必须与本节前表完全一致，并以**纯文本**填写；例如 `recordings.read` 是有效 scope，而 Markdown 链接 `[recordings.read](http://recordings.read)` 不是。JSON 语法错误、无效 ID / token 长度或 `scopes` 不是数组时，该记录会被忽略，输入令牌将无法匹配；scope 数组里的未知值则会被单独过滤掉，令牌身份仍可能验证成功，但没有可用工具。建议每人一条配置，`id` 使用可辨识但不含个人敏感信息的工号别名；审计只记录这个 ID，不构成登录账号或实名认证。轮换时从环境 JSON 中移除旧令牌、加入新令牌并重启服务。

若现场需要额外能力，在该操作员的 `scopes` 与管理员 allow-list 中**同时**增加对应项：例如启动当前侧已配置数据源需 `engine.start` + `start_current_source`；下载允许的数据需 `data.export` + `export_csv`。完整映射见本节上方工具 / scope 表。不要为了省事一次授予全部 scope。

### 6.4 现场运维：验证、预览、确认

1. 使用 `local` 或获准的 `cloud` 模型；不要选 `builtin` 期待其执行工具。
2. 在聊天区「操作员令牌」框输入操作员凭证，点击「验证操作权限」。确认显示的操作员 ID 和可用工具符合现场授权；管理员口令不能代替此步骤。
3. 首轮建议只验证 `list_recordings`、`list_profiles` 等只读工具。提出操作请求后，逐项检查预览中的工具名、参数、影响描述、当前总线 / 分路侧别和有效期。
4. 只有确认参数与影响无误后才点击「确认执行」。模型输出本身不会执行操作；服务端会在确认时重新验证令牌、scope、管理员开关、提案期限和侧别。高风险工具另需输入预览提供的 6 位二次确认码。
5. 提案默认 5 分钟过期且只能执行一次；刷新页面会清除页面内存中的操作员令牌，需重新输入并验证。总线 / 分路侧分别授权、分别确认。

### 6.5 按角色交接与验收清单

- **实施工程师**：记录变量注入位置、服务 unit / 容器名、重启方式和回滚办法；确认变量进了实际服务进程，而非仅存在交互 shell；配置改动后检查助手管理员状态与操作员验证结果。若仍报“尚未启用”，先查服务管理器环境配置并重启，不要把口令粘到浏览器以外的日志里。
- **交付工程师**：按交付范围分配独立操作员 ID 与最小 scope；将管理员口令、操作员 token 放在部署方 secret 管理位置，单独交接，不写进代码仓库；保持审计开启、云端工具关闭，除非客户明确批准数据发送与风险控制。对外提供服务须配置 HTTPS / 网络访问控制；本应用没有账户登录 / SSO。
- **现场运维**：先做只读列表验证，再按审批添加 `engine.start` / `data.export` 等权限；确认卡片侧别是当前工作侧，必要时取消而非猜测。`clear_nilm_events` 仅清当前侧内存事件，不删磁盘 CSV，也不是“清缓存”。

排障速查：

| 提示 / 现象 | 检查项 |
| --- | --- |
| 仍显示“尚未启用” | 变量是否设置在真正运行服务的环境；变量名大小写；服务是否已重启 / 容器是否已重建 |
| “管理员口令无效” | UI 输入是否与服务端环境值完全相同；不要把 JSON 引号或空格当作 token 一部分 |
| “操作员令牌无效或已撤销” | 身份校验没有在服务进程加载的记录中找到完全匹配的 token。先查 `GET /api/assistant/config` 的 `operator_tokens_configured`：`false` 时检查服务管理器环境、JSON 数组语法、`id` / token 长度与重启；`true` 时检查 UI 是否输入了当前 JSON 中的操作员令牌（不是管理员口令、旧令牌或新生成但未同步到服务的令牌）。管理员口令已启用不代表操作员列表已加载 |
| 验证通过但没有可用工具 | scope 必须是 `recordings.read` 这样的精确纯文本；Markdown 链接 / 错字会被过滤，使令牌可能通过身份校验但 scope 为空。再检查模型是否为 builtin、全局工具开关、allow-list；若云端模式，另查云端工具开关 |
| 提案确认被拒绝 | 检查提案是否过期 / 已处理、确认侧别是否一致、令牌是否仍具备 scope；高风险动作是否填写正确二次确认码 |

### 6.7 明确指令路由与模型选择边界

对 local / cloud 且不带图片的会话，若用户输入与某个注册工具的标题完全一致（可带“请 / 请帮我 / 帮我 / 麻烦”等礼貌前缀），且该工具经服务端空参数校验可直接调用，服务端会确定性地创建该工具的待确认提案，不再让模型在多个工具间猜选。数据源启动另有一条窄范围的确定性规则：以下六种表达均直接路由到 `start_current_source`，不让模型把“播放”误判为调速，也不回退到查询工具：

- “播放离线数据源CSV文件”
- “播放离线数据源”
- “播放数据源”
- “启动离线数据源CSV文件”
- “播放数据源与控制中的离线数据源CSV文件”
- “启动数据源与控制中的离线数据源CSV文件”

这条规则只识别明确的“播放 / 启动 / 开始播放 + 数据源”短命令，并对“数据源与控制中的”等已知页面位置词做有限规范化。命令前允许“马上 / 立即 / 赶紧 / 现在 / 先 / 直接 / 就”等修饰语，例如“请马上开始离线数据源”也会直接路由到 `start_current_source`。“播放”或“启动”本身不表示修改速度；`set_playback_speed` 仅用于用户明确要求改播放速度 / 倍速并提供目标数值的请求，它只改配置，不会启动数据源。若用户说的是播放 / 启动离线来源，服务端还会核验当前侧来源确为 `csv_file` / `csv_tail`；“CSV文件”不等于文件选择请求，也不会推断路径、file ID 或替换当前来源。当前侧未配置来源、来源类型不匹配、文件不可用或来源已运行时，服务端返回相应提示，不会绕过检查。

确定性路由仍先检查当前侧配置、运行状态、工具 allow-list、操作员 scope 与模型类型开关，并只创建待确认卡片，不会跳过用户确认、高风险二次确认、侧别绑定或审计。目标工具未进入本轮授权清单时返回权限 / 配置错误，不调用相似查询工具兜底。带必需参数的其他工具、其他自由表达、附图请求及 builtin 通道仍由原有问答 / 模型工具选择流程处理；对这些表达，系统没有保证每个模型都能选对工具。测试只能验证目录、schema、授权过滤、dispatcher 与确定性路由契约；真实 Qwen / 其他 provider 的自然语言选工具效果，必须连接对应模型服务实测。模型的 `tool_choice=auto` 不能当作全工具自然语言识别通过的证据。

待确认提案保存在服务进程内，默认 5 分钟过期、绑定操作员和总线 / 分路侧、单次使用；重启会使待确认提案和内存临时导出链接失效。表中标记“普通 + 二次”的高风险操作均要求输入服务端生成的 6 位二次确认码。`clear_events` / `clear_nilm_events` 只清当前侧内存事件，不删除磁盘 CSV，也不等同清缓存。工具审计默认追加到数据目录的 `tool_audit.jsonl`，管理员可在面板读取；审计记录不能替代操作系统级日志备份。

总线 / 分路侧请求必须分别走 `/api/assistant/...` 和 `/api/branch/assistant/...`；确认端点会再次检查当前侧，不能从另一侧确认。`visible_views` 只控制前端入口在哪些业务页显示，不是用户身份认证或账户权限。向不可信网络开放服务前，必须由部署方配置 HTTPS / 网络访问控制并保护管理员口令与操作员令牌。

### 6.8 有限意图契约与模型结果服务端校验

46 个注册工具各自在 `app/assistant_intents.py` 中维护有限意图说明、动作词 / 目标词、至少两个正例与反例、参数规则及必要字段澄清指引；这些规则与 `TOOL_CATALOG` 的参数 schema 做目录一致性检查，并作为受控模型工具描述的一部分。自然语言规范化只覆盖受限格式变化，不把引述、否定、过去时、动作冲突、多个对象或复合步骤当作单一确认命令。

模型的工具调用只是候选，不是用户授权，也不构成工具已执行的事实。创建提案前，服务端将候选工具与**本轮当前用户消息**的唯一意图匹配，逐字段核对枚举 / 布尔值、显式数字、参数语义和当前受控资源 ID，再通过现有严格 schema 校验；授权、当前侧、资源存在性及运行状态仍由既有服务端检查独立决定。模型猜出的可选值不会扩展请求；若用户提到某字段但返回值与之不符，或必填值缺失、对象 / 动作不唯一、参数冲突 / 不合法，系统不创建待确认提案，并用澄清问题说明缺少或冲突的项目。模型同时返回的“已完成”等文字在工具调用被拒绝时会被丢弃，不会显示为成功结果。

普通 JSON 响应增加 `clarification: true|false`，拒绝工具提议时 `proposal` 为 `null` 且 `answer` 为澄清内容；SSE 在同样的澄清文字 `delta` 后发送 `type=clarification` 标记，不发送 `type=proposal`。为避免模型先输出误导文字再输出无效工具调用，带工具 schema 的 SSE 文本会缓冲到本轮模型决策完成：有效调用只显示服务端生成的预览提示；无效调用只显示澄清；没有工具调用时再释放普通回答。这样的缓冲可能增加流式答案的首字延迟。

自动回归覆盖 46 项契约的目录、正反例、schema 字段，以及模型工具名不匹配、否定 / 疑问、复合动作、缺参、歧义枚举 / 资源、错误数字、JSON 与 SSE 澄清路径。测试使用受控假响应验证服务端拒绝，不代表真实 Qwen / 任意 provider 的工具选择质量已验收；接入具体模型后仍须在部署端测试并核对有效工具权限清单。原确认、scope、allow-list、高风险二次确认、侧别绑定、执行复验与审计边界不因意图解析而放宽。

### 6.9 意图路由排查日志

后端会记录路由与工具校验过程，便于排查“播放离线数据源”是否走确定性启动路由、是否因附图 / 后端类型进入模型路径、模型是否返回了调速工具，以及服务端最终接受还是澄清。针对包含“离线 + 数据源 + 播放 / 启动 / 开始 / 运行”的请求，会在 `WARNING` 级输出 `assistant_route_diagnostic`；这是有意用于现场排查的诊断事件，不表示操作失败。其他普通路由与模型请求元数据使用 `INFO`。`POST /api/assistant/chat` 的有效请求响应头带有 `X-Assistant-Trace-ID`，可用其将浏览器 Network 响应与后台日志关联；服务端 `cli.py serve` 默认日志级别为 `warning`，目标诊断事件默认可见。若需同时查看普通路由 / 模型请求元和启动信息，以 `python cli.py serve --log-level info` 启动；启动时 `服务启动 version=… pid=… assistant_module=… modified=…` 可证明进程实际加载的代码目录与文件时间，用于排除未重启或指向旧目录的旧进程。

日志只包含 trace ID、side、backend、附图数量、路由结果、工具可用性布尔值、受限来源类型 / 状态、模型候选工具名、意图候选及分数、固定 schema 参数**字段名**和校验结果；不记录原始问题、参数值、截图内容、API Key、操作员令牌、模型 endpoint、文件路径或操作员 ID。无需开启 `log_queries`；既有 `log_queries` 开关若另行启用，会按原设计记录问题文本，应依部署隐私策略决定是否开启。

**未开放 / 未覆盖操作（安全边界）**：助手不是通用代理。它不提供任意 shell、Python、SQL、文件系统读写、任意路径、任意 URL / API 调用，也不允许模型直接传入完整配置对象。仅能使用本表固定 schema 的业务工具；录波 / 画像由服务端受控目录签发 opaque ID，并在执行时重验路径边界与文件状态。数据源的任意路径、TCP 主机 / 端口、CSV 列映射、播放自定义时间窗、输出目录 / 文件名、配置文件加载 / 保存路径、任意历史文件删除、整体缓存清理、设备画像文件删除，以及助手管理员设置 / API Key / 云端档案 / RAG 导入删除 / 审计读取，都不作为模型工具开放；这些操作须由现有页面或管理员接口完成。工具覆盖的是用户级计算、查询、分析和有限配置，不代表暴露了软件全部 HTTP API 或所有 UI 偏好。

## 7. 主要接口与验证

- `GET /api/assistant/documents`：获取内置文档元数据与全文，供同页文档栏初始化。
- `GET /api/assistant/config`：读取不含密钥正文和敏感词正文的公开设置。
- `GET /api/assistant/knowledge`、`POST /api/assistant/knowledge/import`：查看 / 导入管理员附加知识。
- `POST /api/assistant/chat`：builtin、local 或 cloud 问答；支持 JSON 与 SSE 流式响应。非流式响应包含 `proposal` 与布尔型 `clarification`；澄清时 `clarification=true` 且 `proposal=null`。SSE 使用 `type=proposal` 携带待确认预览，`type=clarification` 提示意图 / 参数需要用户补充且不创建提案。有效 JSON / SSE 请求会在响应头返回 `X-Assistant-Trace-ID`，用于关联后台意图路由诊断日志。
- `GET /api/assistant/tools/identity`：用 `X-Assistant-Operator-Token` 验证操作员与当前模型可用工具，不回传令牌。
- `POST /api/assistant/tools/confirm`、`POST /api/assistant/tools/cancel`：提交 / 取消提案；分路侧使用 `/api/branch/assistant/tools/...`。
- `GET /api/assistant/tools/export/{id}`：在身份、scope、侧别与时限校验后下载当前侧临时 CSV。
- `GET /api/assistant/tools/audit`：管理员读取 `tool_audit.jsonl`。
- 文档生成 / 检查：`python tools/generate_assistant_docs.py` / `python tools/generate_assistant_docs.py --check`。
- 回归入口：`tests/test_assistant.py`、`tests/test_server.py`、`tests/test_web_ui.py`、`node tools/ui_assistant_check.cjs`。
