# 智能问答模块说明文档

## 1. 模块定位

“智能问答助手”是电气量计算与负荷辨识平台内的**调参辅助文档助手**。它在当前业务页面以固定侧栏呈现，左侧浏览产品文档、操作手册与参数清单，右侧提问、查看回答和引用。它优先帮助工程师 / 运维 / 交付人员查找平台参数、理解算法配置、设计可复现实验和排查回放结果。

问答本身仍以指导为主；另有可选的**确认式受控业务工具**：自然语言只会触发预览卡，不直接执行。用户需检查工具名、参数、影响和侧别，明确点击确认后，服务端再次验证操作员令牌、scope、配置开关、提案有效期与侧别，再调用固定注册的业务 API。助手不会运行 shell、SQL、任意 URL 或模型提供的文件路径，也不会把“待确认”描述成“已执行”。未配置操作员令牌 / scope 或管理员关闭工具时，操作只能拒绝执行。

## 2. 启动时的本地知识库

助手服务初始化时从仓库内的固定、已跟踪文件构建只读内置文档库；页面初始化时通过同源接口一次加载文档目录与全文，便于在侧栏浏览。内置资料也参与 builtin、local、cloud 三种问答通道的本地检索：

| 文档 | 内容来源 |
| --- | --- |
| 软件设计文档 | README 的系统定位 / 目录与配置 / 验证 / 生产流程章节、`REPORT.md` 稳定设计结论、设备画像算法方案 |
| 软件使用文档 | 完整 `README.md` 用户手册 |
| 软件部署说明文档 | README 快速开始、本地部署、Web 启动与生产流程章节 |
| 软件算法调参与验证文档 | 完整 `NILM_TUNING_GUIDE.md` |
| 平台参数清单 | 由 `AppConfig` 代码默认值、`configs/default.json`（总线侧模板）与 `configs/branch.json`（分路侧模板）合并路径生成；三类来源独立成列，并对每侧缺少的字段标注未显式配置 |
| NILM 数据定义与质量说明 | `NILM_DATA_DICT.md` |
| 智能问答模块说明文档 | 本文件 |

参数清单分别展示**代码默认值、总线模板值、分路模板值**，都不是用户当前有效值。运行时配置文件、环境变量、页面热更新、命令行覆盖和两侧各自的配置加载规则都可能改变实际值；模板列若显示“未显式配置”，不能据此推断最终值。参数解释优先结合调参手册、README 配置章节及代码校验规则。

内置知识只读取上述明确列出的项目文档与模板，不读取 `tmp/`、用户真实数据、助手管理员上传目录或运行产物。修改这些文档后需重启服务，重新构建内置语料；用户导入的附加文档仍由管理员单独维护。

## 3. 如何使用

1. 在允许显示入口的业务页点击“智能问答助手”，同一页面右侧固定打开侧栏；无需跳转独立页面。
2. 在“文档”区搜索并选择软件设计、使用、部署、调参验证、参数清单、数据字典或本模块说明。选中后可在侧栏阅读完整 Markdown 文档。
3. 在“问答”区提问。建议写明当前业务页、总线侧 / 分路侧、数据源、接线方式、PT/CT、检测量和希望验证的现象；参数问题优先从平台参数清单检索，并结合完整说明文档回答。
4. 需要实验建议时，明确目标事件 / 设备、已有真实数据、当前参数和判定标准。要求助手给出“前置条件 → 单变量改动 → 操作命令或页面路径 → 预期现象 → 记录项 → 通过 / 失败判据 → 回滚方式”。
5. 若管理员已启用工具且你持有对应操作员令牌，在“操作员令牌”框输入令牌并点“验证操作权限”。请求操作后先检查预览卡中的工具、参数、影响、侧别和有效期；页面会显示待确认、过期或已处理状态。高风险操作还要输入二次确认码，再点“确认执行”；也可取消提案。令牌只留在当前页面内存，刷新即清除；不应复制到 URL、日志或浏览器持久存储。无效或已撤销的可选令牌不会阻断只读问答，但不会提供工具；身份校验端点仍报告认证错误。
6. 对回答中的参数或命令，以引用文档和当前运行配置交叉核对；不要把出厂默认值误当成运行期实际值。若需要的是未注册工具、任意文件操作或“清除缓存”，助手会拒绝，不会猜测替代动作。

对话会话仅保存在当前页面内存；可切换、清空上下文或删除会话，刷新页面后全部清除。文档侧栏是只读浏览器，不会改变业务配置。

## 4. 问答通道与数据边界

- **内置知识库（builtin）**：默认且零模型依赖。仅在应用服务器本机检索内置与管理员导入的文档，返回相关摘录和引用；不调用本地或云端大模型。它不是生成式回答，未检索到资料时会明确提示。
- **本地模型（local）**：由应用服务把问题、必要的对话历史和检索片段发送到所配置的本机 / 内网 OpenAI-compatible 接口。本地请求不经系统 HTTP 代理。
- **云端模型（cloud）**：会把问题、对话历史和命中的检索片段发送给所配置的云端服务。发送前会检查明显密钥模式、管理员敏感词和常见本地文件 / 录波路径及文件名；这是保守的规则拦截，不是完整 DLP，不能保证识别所有个人信息或业务秘密。未经授权的数据不要发往云端。
- **工具执行边界**：云端工具提议默认关闭（`cloud_tools_enabled=false`），须管理员显式单独打开，并且每个操作员仍需持有工具对应 scope；确认时服务端重新授权。操作员令牌是可选的：无效或已撤销的令牌只会禁用工具能力，不会阻断只读问答；身份端点仍拒绝无效令牌。工具执行结果只回到页面，不会追加发送给云端模型。
- **管理员附加文档**：文本文件由管理员显式导入，保存在本地助手数据目录；它们与程序内置资料分开管理。清空操作只影响管理员导入的资料，不会删除随程序加载的内置文档。
- **引用名脱敏**：当前服务端沿用既有 `branch.hide_ui` 作为来源名称脱敏判据，这是暂定映射（该字段原义为隐藏分路侧界面，并非助手专属开关）。若该配置为真，问答响应中的引用名称和答案文本会脱敏；不要把客户端传入值当成安全控制。

## 5. 调参实验回答规范

调参建议应尽可能可复现、可逆、可判读：

1. **先确认口径**：两侧 / 接线 / PT、CT / P 或 I / 时间戳与采样率 / 原始文件范围；未知项标记为待确认。
2. **建立基线**：保留原配置，记录配置文件来源、软件版本、数据文件摘要、数据时间范围、事件真值与现有输出。
3. **单变量实验**：一次只修改一个主要参数；解释参数作用、方向预期、适用边界和可能副作用。涉及多个互相制约的参数时，说明分组顺序和回退点。
4. **给出可执行方案**：列出页面路径或完整命令、输入文件、输出目录、预期字段 / 事件数量和需要保存的日志；命令必须来自项目现有帮助文档或代码，不得编造。
5. **写清判据**：用已知真值对账，分别报告命中、漏报、误报、时间偏差、幅值 / 置信度与失败原因；经验阈值标成经验值，不能承诺必然效果。
6. **保护现场状态**：提醒先备份配置与实验输入；没有执行工具时只提供操作步骤。用户完成实验并回报真实结果后，再基于实录分析下一步。

## 6. 管理员配置与维护

管理员可在面板设置中选择 builtin / local / cloud、维护模型地址与参数、启用 RAG、导入附加文本知识、配置敏感词和控制入口可见页面。配置与附加知识写操作受服务端 `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN` 保护；API Key 不会经公开配置接口回传。可持久化使用的密钥应通过服务端环境变量设置，避免仅在进程内存中的 UI 临时值。

受控工具设置包含全局 `tools_enabled`、工具 allow-list `enabled_tools`、独立 `cloud_tools_enabled` 和 `tool_audit_enabled`。新安装默认 `tools_enabled=false`、`cloud_tools_enabled=false`、审计开启。管理员 API 会拒绝非列表或含未注册名称的工具 allow-list；读取旧配置时若 `enabled_tools` 类型损坏，服务端回退为空 allow-list，fail-closed，不会自动启用全部工具。操作员凭证仅从服务端环境变量 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` 读取，格式为 JSON 数组，例如：

```json
[
  {"id":"field-operator-1","token":"请替换为随机生成的至少 16 字符令牌","scopes":["config.wiring.write","engine.start"]}
]
```

令牌只返回操作员 ID 与 scope，不会回显凭证；scope 只接受下表列出的精确值。至少使用随机高熵令牌，并通过部署环境的 secret 管理功能注入；不要将真实令牌写入仓库、配置文件或浏览器持久存储。该方案没有用户账号 / SSO，审计身份是令牌配置的 operator ID，不等价于强实名认证。

| 工具 | 所需 scope | 受控行为与限制 |
| --- | --- | --- |
| `set_profile_parameters` | `profile.thresholds.write` | 修改当前侧画像匹配 `d2_max` / `min_confidence`，范围严格校验并热更新配置 |
| `set_wiring_mode` | `config.wiring.write` | 只切换当前侧 `3p3w` / `3p4w`，PT/CT 与其它设置不变 |
| `load_latest_profile` | `profile.load` | 只加载受控 output 目录内标记为当前侧的最新画像；确认时校验文件仍未变化 |
| `start_current_source` | `engine.start` | 只启动当前侧已配置数据源；不接收模型路径、不重启已运行任务、不联动另一侧 |
| `export_csv` | `data.export` | 导出当前侧辨识事件内存列表、电气量结果或已勾选曲线；临时下载链接 10 分钟有效 |
| `list_recordings` | `recordings.read` | 仅列 data / output 下文件元数据，不读文件内容 |
| `list_profiles` | `profiles.read` | 仅列当前侧 output 画像元数据，不读波形 |
| `clear_nilm_events` | `nilm.events.clear` | 只清当前侧内存 NILM 事件列表；不删磁盘 CSV，也不代表清缓存 |

待确认提案保存在服务进程内，默认 5 分钟过期、绑定操作员和总线 / 分路侧、单次使用；重启会使待确认提案和内存临时导出链接失效。`clear_nilm_events` 为高风险动作，另要求输入服务端生成的二次确认码。工具审计默认追加到数据目录的 `tool_audit.jsonl`，管理员可在面板读取；审计记录不能替代操作系统级日志备份。

总线 / 分路侧请求必须分别走 `/api/assistant/...` 和 `/api/branch/assistant/...`；确认端点会再次检查当前侧，不能从另一侧确认。`visible_views` 只控制前端入口在哪些业务页显示，不是用户身份认证或账户权限。向不可信网络开放服务前，必须由部署方配置 HTTPS / 网络访问控制并保护管理员口令与操作员令牌。

## 7. 主要接口与验证

- `GET /api/assistant/documents`：获取内置文档元数据与全文，供同页文档栏初始化。
- `GET /api/assistant/config`：读取不含密钥正文和敏感词正文的公开设置。
- `GET /api/assistant/knowledge`、`POST /api/assistant/knowledge/import`：查看 / 导入管理员附加知识。
- `POST /api/assistant/chat`：builtin、local 或 cloud 问答；支持 JSON 与 SSE 流式响应。非流式响应包含 `proposal` 字段；SSE 使用 `type=proposal` 事件携带待确认预览。
- `GET /api/assistant/tools/identity`：用 `X-Assistant-Operator-Token` 验证操作员与当前模型可用工具，不回传令牌。
- `POST /api/assistant/tools/confirm`、`POST /api/assistant/tools/cancel`：提交 / 取消提案；分路侧使用 `/api/branch/assistant/tools/...`。
- `GET /api/assistant/tools/export/{id}`：在身份、scope、侧别与时限校验后下载当前侧临时 CSV。
- `GET /api/assistant/tools/audit`：管理员读取 `tool_audit.jsonl`。
- 回归入口：`tests/test_assistant.py`、`tests/test_server.py`、`tests/test_web_ui.py`、`node tools/ui_assistant_check.cjs`。
