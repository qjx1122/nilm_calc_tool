### 2.1 环境要求

| 项 | 要求 | 状态 |
| --- | --- | --- |
| 操作系统 | Linux / macOS / Windows 10+ 均可（纯 Python + 浏览器，无 GUI 依赖） | Linux ✅沙盒实录；Windows/macOS 🔶未实测 |
| Python | **实测 3.11.2**。语法层面兼容 3.9+：用 `ast.parse(feature_version=(3,9))` 扫描全部 31 个 `.py` 文件无不兼容语法，且未使用 3.10+ 专属 stdlib（`match`/`pairwise`/`KW_ONLY`/`tomllib` 等） | 3.11.2 ✅；3.9/3.10 运行时 🔶未逐版实测 |
| CPU/内存 | 单核即可跑实时（实测 6400 点/s 实时摄入，速率 6398–6400 点/s）。内存主要是环形缓冲：`容量 = ceil(最长窗长 × fs × 1.5) + max(每块点数, 64)`（且不小于 fs），按 7 通道 float64 计——实测 1s 窗 + 块 640 → 容量 10240 点 ≈ 0.55 MB；1s 窗 + 块 1280 → 10880 点；5s 窗 + 块 1280 → 49280 点 ≈ 2.7 MB。窗长变化时缓冲自动扩容并保留已有数据尾部 | ✅沙盒实录（2 核 / 3 GB 环境；公式见 `elec_tool/engine.py:LiveEngine.__init__`） |
| 浏览器 | 任一现代浏览器（Chrome/Edge/Firefox），需支持 WebSocket；不支持时前端自动降级为 1.5 s 轮询 | ✅（降级逻辑见 `app.js:startPolling`） |
| 磁盘 | 代码 + 依赖 ≈ 200 MB；结果 CSV 视时长而定（实测 5 s 数据导出 26 次结果 = 1.4 MB） | ✅沙盒实录 |

```bash
.venv/bin/pip download -r requirements.txt -d ./wheels

# 拷贝 wheels/ 与代码到目标机后，完全无网安装
python3 -m venv .venv
.venv/bin/pip install --no-index --find-links ./wheels -r requirements.txt

# 验证（实测输出）
```

**(c) 内网离线安装 —— Windows 目标机** ✅下载侧实录 / 🔶安装侧未实测

wheel 与平台绑定，必须在打包时指定目标平台。**坑（实测踩过）**：直接用 `-r requirements.txt` 跨平台下载会失败——
`uvicorn[standard]` 的 extra 会拉 `uvloop`，而 uvloop 没有 Windows wheel，pip 报 `ResolutionImpossible`（补 `--implementation cp --abi cp311` 也无效）。
解决办法是**显式列包**、不带 `[standard]` extra：

```bash
# 在联网机器上（实测得到 24 个包 / 18 MB，含 numpy-2.4.6-cp311-cp311-win_amd64.whl）
pip download --platform win_amd64 --python-version 3.11 --implementation cp --abi cp311 \
    --only-binary=:all: -d ./wheels_win \
    numpy fastapi uvicorn websockets pytest httpx

# 目标 Windows 机器上（🔶未实测，命令为 pip 官方离线用法）
py -3.11 -m venv .venv
.venv\Scripts\pip install --no-index --find-links .\wheels_win numpy fastapi uvicorn websockets pytest httpx
```

> `requirements.txt` 已用 PEP 508 平台标记分流：Windows 上联网 `pip install -r requirements.txt` 会自动选 `uvicorn` + `websockets`（不拉 uvloop）。该分流逻辑在 Linux 侧实测生效，**Windows 侧未实测 🔶**。

**(d) 最小安装（只用 CLI，不要 Web）**

```bash
.venv/bin/pip install numpy          # 之后 cli.py 除 serve 外的 6 个子命令都能用
.venv/bin/python cli.py serve        # 会明确报错并给出安装提示，退出码 2：
#   ✗ 未安装 Web 依赖：pip install fastapi 'uvicorn[standard]'
```

**访问**

- 本机：`http://127.0.0.1:8000`
- 局域网其它机器：`http://<部署机 IP>:8000`（默认已绑 `0.0.0.0`；需在防火墙放行该端口 🔶未实测）
- 反向代理（nginx 等）：必须转发 WebSocket 升级头，否则前端自动降级为 1.5 s 轮询（功能不受影响，实时性下降）：
  ```nginx
  location / { proxy_pass http://127.0.0.1:8000;
               proxy_http_version 1.1;
               proxy_set_header Upgrade $http_upgrade;
               proxy_set_header Connection "upgrade";
               proxy_read_timeout 3600s; }        # 🔶配置未实测，为 nginx 官方 WebSocket 代理写法
  ```

**`serve` 参数与环境变量**

| 名称 | 默认 | 作用 | 状态 |
| --- | --- | --- | --- |
| `--host` | `0.0.0.0` | 监听地址（`127.0.0.1` = 只允许本机） | ✅ |
| `--port` | `8000` | 监听端口 | ✅ |
| `--log-level` | `warning` | uvicorn 自己的日志级别（排障时改 `info` 可看到每个请求）；不影响下一行 | ✅ |
| `--app-log-level` | `info` | 程序自己的日志（`elec_tool.*` 记录器：服务启动信息、智能问答路由日志等）的级别，写到标准错误，每行带时间、级别、记录器名。可选 `debug` / `info` / `warning` / `error` / `critical`；只想看警告和错误时用 `warning`。调用方已自行配置日志时只设置级别、不重复输出；直接用 uvicorn 启动时没有这项配置（v0.99.50） | ✅沙盒实录（Linux） |
| `--config` | `configs/default.json` | 配置文件路径 | ✅ |
| `--pt/--ct/--fs/--freq/--hmax/--adaptive/--no-scale/--set-window/--apparent/--reactive` | 见 §6 | 启动时覆盖配置（通过 `ELEC_TOOL_CONFIG` 传给服务，实测 `/api/state` 回读一致） | ✅沙盒实录 |
| 环境变量 `ELEC_TOOL_AUTOSTART` | 空 | 非空则启动即自动跑引擎（否则需在界面点「启动数据源」） | ✅沙盒实录 |
| 环境变量 `ELEC_TOOL_CONFIG_PATH` | 空 | 强制指定配置文件（加载与保存都用它） | ✅ |
| 环境变量 `ELEC_TOOL_PERSIST_CONFIG` | `1` | 置 `0` 则界面改动只留在内存，不落盘 | ✅ |
| 环境变量 `ELEC_TOOL_CONFIG` | 空 | 直接传整份配置 JSON（`cli.py serve` 内部用这个实现参数覆盖） | ✅ |

**数据源面板：4 种输入方式的联动、空值语义与两个保存入口（✅沙盒实录）**

「数据源输入方式」下拉框 4 项与后端 `SOURCE_KINDS` 一一对应；选中后界面**只放开与该源相关的字段**，其余置灰禁用（填了也不生效，置灰是为了不让人白填）：

| 选中 | 可编辑 | 置灰 |
| --- | --- | --- |
| `csv_file` 离线文件 | CSV 路径、每块点数 | 主机 / 端口 / 帧格式 / struct 两项 / 速率 / csv_tail 两开关 |
| `csv_tail` 文件追加 | CSV 路径（**文件或目录**）、从文件末尾开始、跟目录最新文件、每块点数 | 主机 / 端口 / 帧格式 / struct 两项 / 速率 |
| `tcp` TCP 客户端 | 主机、端口、帧格式、每块点数；帧格式选 `binary` 时才放开 struct 格式与字段顺序 | CSV 路径 / 速率 / csv_tail 两开关 |

下拉框下方有一行**随选择切换的填写说明**（`#src-hint`）：例如选 `tcp` 会写明 `text_csv`（每行一条 CSV，可带中文表头）与 `binary`（定长帧，默认 `<7d`＝7 个 double 小端＝56 字节/帧）的区别；选 `csv_tail` 会写明目录模式与「从文件末尾开始」的含义。

**两个保存入口的服务端语义不同，别混用**：

| 按钮 | 请求 | 服务端吃什么 | 用于 |
| --- | --- | --- | --- |
| 保存配置（热更新） | `PUT /api/config` | **深合并**：只更新送出的键，未送的键保留原值 | PT/CT、电压输入口径（相/线）、fs/f_nom、谐波上限、视在/无功口径、数据源默认值 |
| 启动数据源 | `POST /api/engine/start` | 只吃 `source` 白名单键（`kind/path/host/port/frame/block_samples/poll_interval_s/tail_from_end/sim_speed/watch_dir_newest/struct_fmt/struct_fields`）与 `windows` | 换源、换路径、立即开跑 |

> ⚠️ 改了 **PT/CT 或功率口径**后必须点「保存配置（热更新）」：这些键不在 `/api/engine/start` 的白名单内，点「启动数据源」会被服务端**静默忽略**（界面已在提示里指明该点哪个按钮）。

**空输入框＝沿用服务端已保存的值，不是清空**：留空的文本框、非正数或非数字的数字框都不会进入请求体（`PUT` 深合并，省略即保留）。两个实测理由：① 空 `path` 送出去会被拒 `HTTP 400 source.kind=csv_file 需要 source.path（文件或目录路径）`；② 空数字框若按 `+'' === 0` 送出会得到 `HTTP 400 sampling.fs 必须 > 0（当前 0）`。被跳过的字段名会写进保存成功的提示，不静默。

**正在编辑时不会被实时推送打断**：快量每 0.2 s 推一次结果并触发界面刷新；一旦你在本页动过任何控件，自动回填立即暂停并显示「⚠ 界面有未保存的修改…」。点「刷新」＝丢弃未保存修改、按服务端配置重新回填；保存或启动成功后自动恢复回填。

CLI 同等能力：`.venv/bin/python cli.py resample "data/波形_农业排灌_大水泵_80_1.csv" --fs 6400 [--fs-src 3200] [--method fft] [--overwrite] [--format json]`。
库：`from elec_tool.resample import resample_csv; resample_csv(path, 6400, out_dir="data")`。

**注意**：`linear` 降采样无抗混叠（高于新 Nyquist 的谐波会折叠到低频），要做谐波分析请用 `fft`；`fft` 的输出点数 = round(N·fs_new/fs_src)（周期语义），比例非整时实际采样率略有偏差并写入 notes；重采样后播放时请把「配置采样率 fs」改成目标值。

#### 负荷辨识子界面：逐周波事件检测（v0.11）

> 导航「🧩 负荷辨识」。对**逐周波**的 P / Q / I 序列（每周波＝fs/f_nom＝128 点：P=mean(u·i)，Q=基波单频 DFT 无功，I=周波有效值；对象 total/A/B/C）在最近 `nilm.window_cycles` 个周波的滚动窗上并行运行 6 种突变检测算法；每条事件给出**算法、对象、开始/结束时刻（数据时间）、方向（up 投入 / down 切除）、幅值 |ΔP| 与带符号 ΔP / ΔQ / ΔI、事件前后稳态值、算法检验量**，并落盘 `output/nilm/nilm_events_<写入日期>.csv`（v0.58：文件名按墙钟日期）（每事件一行，UTF-8-BOM，逐行 flush，`ELEC_TOOL_NILM_DIR` 可改）。

| 算法键 | 名称 | 原理 | 参数（`nilm.algorithms.<键>`，W＝有功，周波＝cycles） |
|---|---|---|---|
| `threshold` | 阈值差分 | 相邻周波 ΔP ≥ max(min_delta/2, 容差) 为起点；随后 settle 个周波极差 ≤ 容差为终点；起点精修到越过 Δ/2 中线的周波 | `min_delta_w` 50, `settle_cycles` 5, `settle_tol_w` 20, `max_rise_cycles` 40 |
| `two_window` | 双滑窗均值差 | \|mean(后窗)−mean(前窗)\| 的局部极大值 ≥ min_delta 且 ≥ k·σ(前窗) | `pre_cycles` 10, `post_cycles` 10, `min_delta_w` 50, `k_sigma` 3 |
| `cusum` | CUSUM 累积和 | 双侧 Page CUSUM：相对参考均值累积偏差 > h 触发，起点＝累积量最后归零处，触发后重置参考均值 | `drift_w` 10, `threshold_w` 200, `min_delta_w` 50, `settle_cycles` 5 |
| `glr` | GLR 广义似然比 | 高斯均值突变：n/4·(m1−m0)²/σ² 的局部极大值 ≥ 门限（σ² 取两侧方差均值，不低于 noise_w²） | `window_cycles` 15, `threshold` 25, `min_delta_w` 50, `noise_w` 10, `settle_cycles` 5 |
| `steady_state` | 稳态分段（Hart 1992） | 连续 ≥ N 个周波极差 ≤ 容差为稳态；相邻稳态均值差 ≥ min_delta 即事件（起点＝前稳态结束，终点＝后稳态开始） | `tol_w` 30, `min_steady_cycles` 10, `min_delta_w` 50, `max_transient_cycles` 100 |
| `median_diff` | 中值滤波差分 | N 点中值滤波去尖峰后再做阈值差分（单周波尖峰/缺口不触发） | `median_cycles` 5, `min_delta_w` 50, `settle_cycles` 5, `settle_tol_w` 20, `max_rise_cycles` 40 |

- 通用参数：`nilm.enabled`、`save`、`channels`（默认 `["total"]`）、`window_cycles` 300、`min_gap_cycles` 10（同算法同对象去重间隔）、**`rel_tol_pct` 1.0**（容差/漂移/噪声/CUSUM 门限按窗内 |P| 中位数折算，与绝对值取大）、**`min_delta_pct` 0**（最小幅值的相对版本）。阈值单位为 W、按计算口径（启用 PT/CT 时为一次侧）；相对门槛让同一套默认值在 W 级（二次侧）与 MW 级（一次侧）都可用。全部在界面「检测参数」表单热更新（`PUT /api/config {"nilm": …}` 深合并）。
- 去重/确认：每个算法都在整窗上重新评估，只对「终点全局周波序号 > 上次已报终点 + min_gap」且「终点之后已再看到 confirm 个周波」的候选报事件，所以事件会滞后几个周波（≤ 后窗/GLR 窗）出现，且**不随块边界重复**。
- 接口：`GET /api/nilm/events?limit&algos&channel&since_id`、`GET /api/nilm/cycles?n`（最近 n 周波 P/Q/I）、`POST /api/nilm/clear`；WS `type=nilm_event` 推送；`/api/state.engine.nilm_events_total/nilm_cycles`。
- 样例：`.venv/bin/python tools/gen_nilm_sample.py` 生成 `data/nilm_steps.csv`（1000 W → 2.0 s +500 W → 4.4 s −300 W，3.0 s 单周波尖峰）；默认 PT/CT 下 6 种算法均在 **2.000 s ↑750 kW、4.400 s ↓450 kW** 报出（起点误差 ≤1 周波，幅值误差 <1%）。
- **假设与已知特性（可改）**：① 周波按额定频率定长切分（不随频率自适应）；② 事件＝稳态间阶跃，不做负荷类型识别/聚类（辨识的「特征提取 + 事件库」已就位，分类留后续）；③ 双滑窗与 CUSUM 对单周波尖峰会按均值摊成小事件（样例中 60 kW），需要抗尖峰请看中值滤波差分/稳态分段或抬高 `min_delta_pct`；④ 幅值取事件后 settle 均值 − 事件前 settle 均值，暂态（电机启动冲击）期间不计入。
- 验证：`tests/test_r12_nilm.py` 8 项；`tools/ui_r12_check.cjs` 16 项；全量 **257 passed**。
- **仅电流事件检测（v0.36）**：`nilm.quantity` ∈ `auto`（默认）/ `p` / `i`。数据源**只有三相电流、没有电压**（CSV 表头 `时间戳,A相电流,B相电流,C相电流` 会被列映射自动识别，电压按 0）时，`auto` 检测到电压恒为 0 自动改按**逐周波电流有效值 I** 检测，六种算法不变（它们只看一维序列）；`i` 口径下各算法使用独立的 **A 单位阈值**（v0.37：`min_delta_a / settle_tol_a / tol_a / drift_a / noise_a / threshold_a`，默认 0.3 / 0.1 / 0.15 / 0.05 / 0.05 / 1.0 A，按二次侧单相 ≈6 A 给出），W 套不参与；`rel_tol_pct / min_delta_pct` 按窗内 \|I\| 中位数折算后与 A 阈值取较大者（一次侧大电流请用相对门槛）。事件新增字段 `quantity / magnitude / unit`（`i` 时 magnitude=\|ΔI\|，unit=A；ΔP/ΔQ 在无电压时恒为 0），CSV 追加这三列（旧文件改名 `.pre-v036.csv`）；界面「检测量」下拉、表格幅值列自动切为 \|ΔI\|（A）、提示区说明；`quantity=p` 而无电压时 `summary.errors` 明确告警而不是静默 0 事件。样例：`tools/gen_nilm_sample.py --current-only` → `data/nilm_steps_i.csv`。局限：无电压不能分解 P/Q、无功率因数指纹；电压暂降会表现为成对的假事件且无法用电压剔除；负荷辨识页 P/Q/S 趋势在无电压时为 0 线（电流趋势未单独绘制）。验证：`test_r12_nilm` +4、`ui_r12` +9。

#### 离线文件的暂停 / 恢复播放（v0.12）

> 顶栏「暂停」按钮与「数据源」页「暂停播放」按钮（同一功能），**只在离线文件（`csv_file`）源运行且未播完时可用**，其他源置灰并提示。

- **倍速**：「数据源」页「离线文件播放倍速」（1× 真实速率 / 2× / 5× / 10× / 0.5× / 不限速），对应 `source.file_speed`（配置与 CLI 默认 0＝不限速；界面默认 1×）。限速由**节拍钟**（`elec_tool/pace.py`，v0.15.1）按绝对墙钟计算：块时长＝块样本数/本侧 fs，目标时刻＝起点 + 已播数据时长/倍速，误差不累积；暂停后恢复不会突发追赶。联动启动时总线侧与分路侧**共用一只节拍钟并互锁**（任一侧块起点最多领先对侧进度 0.1 s）——两侧播放的数据时刻严格同步，与两侧采样率是否相同无关；CPU 跟不上名义倍速时两侧一起变慢而不是一侧跑飞；先播完的一侧退出互锁，另一侧继续播到自己的结尾。
- **暂停**：引擎线程停止读文件与计算，顶栏状态变「已暂停」，数据时刻、样本数、周波窗、事件表全部原地冻结；期间「刷新快照」、历史曲线、导出、负荷辨识/事件查询照常可用（看的是暂停时刻的缓冲）。
- **恢复**：从暂停处的下一块继续，不重读、不跳过；`duration_s` 限时运行会扣除暂停时长（`/api/state.paused_total_s`）。
- 暂停中点「停止」立即停止；重新「启动」从头（或所选播放起点）开始。对 `csv_tail`/`tcp`/`simulator` 不提供暂停（实时源暂停会丢数据或造成追赶突发，按设计拒绝）。

#### 离线文件时标的 UTC 开关（v0.10）

> 适用 `csv_file`（未启用「自定义播放时间」时）与 `csv_tail`；配置项 `source.file_time_utc`（默认 **false**），界面在「数据源」页「自定义播放时间」勾选框下方；启动数据源时随表单下发，也可 CLI `--file-time-utc`。

| `file_time_utc` | 文件文本时标（`2026-10-12 08:00:00` / `0/00/00 00:12:40.0000`）如何解释 | 曲线 / 落盘 CSV / 事件 上看到的时间 |

| **false**（默认） | 按本机**本地时间**解释（解析时 tz_offset_h＝本机时区偏移，东八区 8） | **与文件中的数据时间一致**（文件 `00:12:40` → 界面 `00:12:40`） |

- 纯数字 epoch 时标是绝对时刻，不受本开关影响；`sampling`/计算结果也不受影响（只平移时间轴的绝对位置）。
- 播放起点 `time` 模式与 `0/00/00` 写法的「当天时刻」比较已按同一偏移还原，所填时刻仍是文件里的时刻。
- **假设（已按此实现，可改）**：① 浏览器与服务端在同一时区（界面用浏览器本地时间格式化 epoch）；② 启用「自定义播放时间」时时间轴由起始时间决定，本开关不显示（起始时间留空＝文件第 1 条时间，仍按本开关解释）；③ 偏移按当前时刻的本机时区取（含夏令时），不按每条数据各自判断；④ TCP 文本帧沿用同一开关。
- 验证：`tests/test_r11_file_time.py` 6 项（`TZ=Asia/Shanghai` 下日期时间 / 0/00/00 / epoch 三种写法、`create_source` 默认偏移、REST 探查与启动透传）；`tools/ui_r11_check.cjs` 11 项；全量测试在 `TZ=UTC` 与 `TZ=Asia/Shanghai` 下均通过。

### 3.6 智能问答模块（v0.99.49）

业务页面右下角的「🤖 智能问答助手」入口支持鼠标 / 触屏拖动，可移动到当前视口内任意位置（位置仅保留于当前页面运行期间）；点击后在**当前业务页内打开固定侧栏**，不跳转独立页面；助手打开时悬浮入口自动隐藏；点击关闭，或在没有更深层覆盖区域时按 Escape 关闭助手后，悬浮入口按当前页面可见权限恢复。桌面端默认显示固定宽度会话管理栏 + 自适应问答区；点击问答标题栏的「收起会话」会隐藏左栏并让问答区占满工作区，点击「显示会话」恢复双栏。窄屏初始收起左栏，按钮显示 / 隐藏覆盖式会话抽屉。切换按钮的文本、提示和 `aria-expanded` 会随状态同步。若视口高度不足以容纳主界面，助手外层会显示纵向滚动条，可滚动访问顶栏、问答区和输入控件；消息、会话和设置仍保留各自的内部滚动区，到达内层边界后滚轮可继续滚动助手外层。“配置与附加知识库”使用 overlay 内普通 `div.assistant-settings-scroll` 承载全部配置内容，而非把滚动责任放在 `<details>` 或其内容体：该 `div` 绝对定位并由 `inset:0` 明确占满设置边界，使用 `overflow-y:scroll`、高对比滚动条和键盘焦点；本地文档 / 完整平台参数的内层滚动到边界后，面板级 wheel handler 转发给此滚动区。设置标题 / 关闭入口保持 sticky / 可达。浏览器或操作系统使用 overlay scrollbar 时，非交互状态仍可能自动淡出；本实现尚未通过目标浏览器现场视觉验收。会话标题可搜索，按最近 5 条 / 其余历史分组，显示时间，支持切换、拖拽排序、右键或更多菜单重命名 / 删除；会话仅在当前页面内存，不会跨刷新持久化。问答区底部提供逐会话“问答后端”下拉（本地模型 / 云端模型 / 内置知识库）；切换已有消息的会话时会提示并新建独立会话，原会话与其后端 / 模型不变。管理员设置中的默认后端仅用于首次与新建会话；用户可在 composer 中覆盖。当前会话为 local / cloud 时显示对应具体模型下拉（保留无障碍名称、不显示可见标题），builtin 隐藏模型选择。底部按钮依次提供“附件”、适用时的模型选择、“发送”和配置入口，窄屏下自动换行；“配置与附加知识库”仍统一放模型配置、本地文档 / 完整参数清单、管理员附加知识、管理员口令和操作员令牌验证。左侧会话管理栏标题固定为“智能问答助手”；右侧仅在当前会话已有非空助手回答或操作提案时显示会话名，新会话或清空上下文后不显示标题。助手定位为**调参辅助文档助手**；服务端 `visible_views` 配置控制入口显示在哪些页面。问答接口当前仍无账号登录；工具执行另需服务端配置的操作员令牌与每工具 scope，且必须先由用户确认。未提供、无效或已撤销的可选操作员令牌不会阻断只读问答，但该请求不提供工具 schema；身份校验端点仍返回认证错误。未配置本地或云端模型时，默认走本地文档检索通道，读取随程序内置加载的文档和管理员附加资料，不连接任何模型服务。

**功能与数据边界**

- 内置文档在 AssistantService 启动时从固定白名单读取：`docs/软件设计文档.md`、`docs/软件使用文档.md`、`docs/软件部署说明文档.md`、`docs/软件算法调参与验证文档.md`、`docs/智能问答助手说明.md`、由代码默认 + `configs/default.json` + `configs/branch.json` 动态生成的平台参数清单，以及 `NILM_DATA_DICT.md`。前四份手册由 `python tools/generate_assistant_docs.py` 从 README、稳定设计报告、设备画像算法方案和调参指南生成，可用 `python tools/generate_assistant_docs.py --check` 查过期；服务启动后改文档需重启才会重载。`GET /api/assistant/documents` 向当前页面一次提供目录与完整正文；该语料参与 builtin、本地模型与云端 RAG；参数问题提高平台参数清单优先级。参数清单三种来源分列，不代表当前运行值，“未显式配置”也不等于已知继承值。
- builtin 是本机检索式摘录，不走 OpenAI-compatible 接口，也不发起模型请求；新安装默认选择该通道。切到本地或云端模型后，统一走 OpenAI-compatible `/chat/completions`：本地接口示例 `http://127.0.0.1:11434/v1`（Ollama）+ `qwen2.5:7b`；云端默认 DeepSeek-compatible URL，调用云端需要 API Key。新安装可在首次创建助手配置前设置 `ELEC_TOOL_ASSISTANT_BACKEND=local|cloud` 指定默认通道；已保存配置时以管理员保存的默认后端为准。
- **后端 / 具体模型选择**：composer 底部按会话提供“本地模型 / 云端模型 / 内置知识库”下拉。local 候选只来自本地服务发现（OpenAI-compatible `/models`，必要时回退 Ollama `/api/tags`）；发现请求只使用管理员已保存的本地服务地址与 API Key，刷新接口不接受请求体指定 endpoint。管理员设置不含本地模型名称；具体本地模型名由当前会话从候选中选择。cloud 下拉只列默认云端模型及管理员已配置的命名档案（档案元数据含模型 ID）；builtin 隐藏具体模型下拉。管理员默认后端用于默认 / 新建会话；切换已有消息会话的后端或模型会经用户确认新建独立会话，不改旧会话。
- **额外云端 API 档案**：管理员可动态维护最多 10 个命名档案，每个档案是一个 HTTPS OpenAI-compatible endpoint + 模型 ID + API Key；同一服务要用多个模型时分别建档。保留旧 `cloud_base_url` / `cloud_model` / `cloud_api_key` 为默认云端配置。`cloud_api_profiles` 中的 ID、名称、endpoint 与模型 ID 默认写入 `output/assistant/config.json`（可由 `ELEC_TOOL_ASSISTANT_DATA_DIR` 改位置），API Key 单独提交、仅存服务进程内存、不写文件也不回传；重启后额外档案需重新输入 Key。档案增删改和密钥操作都由 `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN` 保护。
- 对话通过 SSE 增量显示，带思考状态、停止生成与明确的模型超时 / 连接错误提示；支持安全 Markdown 的标题、列表、引用、代码块、表格和简单数学行内 / 块展示。原始 HTML 不执行，链接只允许 `http(s)`。会话支持标题搜索、最近 / 历史分组、时间、切换、拖拽排序、右键 / 更多菜单重命名和删除；会话与截图只在当前页面内存中，刷新后清空；切换模型会先确认并新建独立会话。
- **波形截图**：可在输入框粘贴，或拖放 / 选择 PNG、JPEG、WebP；单张 ≤3 MiB、每轮最多 3 张且总计 ≤5 MiB。服务端验证 MIME、文件签名、Base64 与请求体大小，不把截图写入助手数据目录；截图以 OpenAI-compatible `image_url` 数据 URI 随本轮模型请求发送。builtin 仅做文本检索、不支持视觉理解；截图需选择支持视觉输入的 local/cloud 模型。云端发送截图前逐次确认；图像内容不经过现有文本敏感词扫描，界面明确提醒不要上传涉密 / 个人信息；这不是图像 DLP。
- 管理员附加知识库仅接受文本：md/txt/json/py/csv/html/yaml/log；单文件 ≤1 MB、一次 ≤10 个 / 5 MB、总量最多 100 个 / 20 MB。它与只读内置文档分开管理；清空操作不删除内置资料。依赖无外部向量服务：按文本分块与词项 TF-IDF 相似度检索，回答附来源名 / 相似度；这是词项检索，不是语义向量检索。
- 来源文件名的服务端脱敏当前跟随总线侧 `branch.hide_ui`；该字段原语义是「隐藏分路侧界面」，不是独立的助手来源显示开关。按本轮暂定规则，字段为真时会对检索上下文、回答、引用和流式分片中的知识库文件名脱敏；如果产品需要独立开关，应另行明确规则。
- 知识库 / 普通配置默认写到 gitignore 覆盖的 `output/assistant/`（可用 `ELEC_TOOL_ASSISTANT_DATA_DIR` 改位置）；Linux 权限尽力收紧为目录 `0700`、JSON `0600`。普通配置会落盘；UI 输入的 API Key **只保存在服务进程内存**，进程重启后消失；部署持久密钥应使用环境变量。默认云端 / 本地配置对应的 `*_API_KEY` 环境变量始终优先；档案级 Key 独立保存在服务进程内存。所有密钥值均不会经 GET 回传，也不会写进 `config.json`。
- 云端模式会把本轮问题、最多 20 条对话历史及命中的知识片段发送给配置的云端服务；服务端会拦截明显的 API Key / 私钥特征、管理员配置的敏感词及常见本地路径 / 数据文件名，但这不是 DLP，也不能保证识别所有个人信息 / 业务秘密。云端工具提议另有 `cloud_tools_enabled` 独立开关，新安装默认关闭；即使打开，仍须操作员 scope 与确认 API 复验。
- 配置与知识库写操作使用 `ELEC_TOOL_ASSISTANT_ADMIN_TOKEN`；未配置时这些写操作返回 403。敏感词正文由独立的管理员接口读取；API Key 无论是否管理员都不回传。对外提供服务时必须使用 HTTPS / 受信任内网并保护管理员口令；聊天接口本身没有账户登录，限流（每客户端 60 秒 12 次、全局最多 3 个活跃模型请求）只能降低滥用，不能替代网络访问控制。

**受控工具执行（可选，默认关闭）**

操作员令牌由服务端环境变量 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` 配置为 JSON 数组，每项为 `{"id":"...","token":"至少 16 字符随机令牌","scopes":["精确 scope"]}`。令牌只在页面内存、不会写入 `localStorage` / `sessionStorage`。管理员可在“受控业务工具与审计”中设置全局开关、单工具 allow-list、云端独立开关与审计开关；若持久配置中的 `enabled_tools` 不是列表，服务会回退为空 allow-list（fail-closed），不会放大成全部工具。模型工具调用只返回待确认预览；预览卡显示有效期及待确认 / 过期 / 已处理状态。确认时服务端重新验证令牌、actor、scope、proposal TTL、侧别和高风险二次确认码，然后走现有业务 API。待确认操作进程内保存、5 分钟到期、单次执行。

当前注册 **46 项**固定业务工具，完整的逐工具 ID / scope / 影响 / 确认要求与不开放操作见 [`docs/智能问答助手说明.md` §6.6「业务工具覆盖矩阵」](docs/智能问答助手说明.md)。覆盖运行与配置摘要、结果 / 历史 / 事件 / 跨侧对比、数据源生命周期、受控录波分析 / 重采样 / CT 估算、设备画像、CSV 导出、白名单配置更新、内存事件清理和算法自检。工具只接受封闭参数 schema；录波与画像使用服务端登记的 opaque ID，不接收模型任意路径；不开放 shell、SQL、Python、任意文件或任意 API。高风险配置 / 停止 / 文件生成操作须额外输入二次确认码。`clear_nilm_events` 仅清当前侧内存事件，不删除磁盘 CSV、也不等同清缓存。工具审计默认追加至助手数据目录 `tool_audit.jsonl`。CSV 临时下载在内存保存 10 分钟；下载时再校验操作员 / scope / 侧别。提案在创建时记下目标侧；2026-11-06 起，从任一侧的确认端点（`/api/assistant/tools/...` 或 `/api/branch/assistant/tools/...`）确认，都按提案记录的侧执行。

**一句话发出后服务端怎么处理（v0.99.50）**

详细说明在 [`docs/智能问答助手说明.md`](docs/智能问答助手说明.md) §6.7～§6.10，这里只列要点：

- **三条路由，依次尝试**：① 确定性路由——工具标题原文和启动 / 暂停 / 恢复 / 停止短命令，直接生成待确认卡片；② 意图识别直达（2026-11-06 加入）——服务端按 `configs/intent_actions.csv` 给这句话打分，只认出一个不需要参数的工具时直接生成卡片，其中“查询运行状态 / 查询计算配置”两项直接返回结果、不需要确认（v0.99.50 起：识别把握不足时改交模型；每次直接返回在审计文件 `tool_audit.jsonl` 里记一条 `status=direct_read`）；③ 其余交给模型，模型选的工具只是候选。
- **澄清**：模型选的工具与这句话对不上、缺参数、参数没有依据或一次提出多个动作时，服务端不生成卡片，回答改为以“我暂未创建操作预览”开头的澄清问题，前端在回答上方标出“待澄清：未创建操作预览”。只要模型提出了工具调用，模型自己写的文字（例如自称已经执行）一律不显示。JSON 响应里 `clarification` 为 `true`，SSE 有 `type=clarification` 帧。
- **侧别（v0.99.50 起三条路由一致）**：话里只点名一侧（“总线侧 / 分路侧”）时，卡片绑定被点名的一侧，前置条件、画像和录波清单也用那一侧的；没有点名或说“当前侧”时是提问页面所在的一侧。在总线侧页面说“暂停分路侧数据源”，得到的是分路侧的卡片，检查的是分路侧是否在运行。“Modbus”里的 bus 不算总线侧。一句话同时点名两侧时不生成卡片（确定性路由返回 400，模型路径返回澄清）；要两侧一起启停，只说“总线侧”，总线侧的启停会按联动规则连带分路侧。“只 / 仅 / 单独”不改变执行内容：卡片绑定总线侧时，影响说明里会写明“系统不支持只作用于总线侧”。
- **启停的前置条件**（前两条路由，按目标侧的数据源状态，不满足时返回 409 并说明原因）：启动——已在运行或已暂停时拒绝；暂停、停止——未在运行时拒绝；恢复——只有已暂停时才生成卡片。
- **延时**：系统不能延时、定时执行。“15秒过后启动数据源”“稍后查看运行状态”“播放完之后停止数据源”这类话在前两条路由上返回 400；单个“后”字不算延时，“查看后台重采样任务状态”“查询最后10条电能质量事件”可以正常处理。
- **让助手多认一种说法**：编辑 `configs/intent_actions.csv` 对应工具那一行的 `actions` / `targets`（词之间用半角分号 `;`），保存为 UTF-8（存成 GBK 也能读），**重启服务**。文件格式不对时服务无法启动并报出原因；用了全角分号或同一工具写两行不会报错但不生效。改完先运行 `python -m pytest -o addopts='' tests/test_assistant.py -k intent -q`。各列含义、打分规则和报错对照表见说明 §6.10。
- **排查某一句话走了哪条路**：每个问答响应带响应头 `X-Assistant-Trace-ID`，服务端日志按这个追踪号记录路由和结果。v0.99.50 起，用 `python cli.py serve` 启动时这些日志默认输出到标准错误，每行带时间、级别、记录器名，正常生成卡片的请求也有记录；级别用 `--app-log-level` 调整（§3.1）。直接用 uvicorn 启动时仍然只有 WARNING 及以上的行。事件名和字段的含义见说明 §6.9。
- **已知限制**（2026-11-11 实测，未修复）：只给出时刻的说法不算延时，“明天8点启动总线侧数据源”会得到一张**立即**启动的卡片；数据源已经暂停、或不是离线文件时说“暂停”仍会生成卡片（确认后没有变化，或返回 400）；“电能质量事件有哪些类型”这类知识性问句会被认成查询，工具可用时得到查询卡片而不是文字回答；“查询运行状态 / 查询计算配置”直接返回的是 JSON 原文。完整清单见说明 §6.8 与 `STATUS.md`「下一步」。

**操作员验证失败的判读**

- **“操作员令牌无效或已撤销”**表示服务端从 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` 解析出的有效记录里，没有一条令牌与输入值匹配。管理员状态显示已启用，只能说明服务读到了管理员口令，不代表它也读到了操作员令牌。先检查变量是否注入了实际服务进程、JSON 是否有效，以及 UI 输入是否是 JSON 内同一串操作员令牌；不要重新生成后仍用旧服务环境。`GET /api/assistant/config` 中的 `operator_tokens_configured` 可安全显示服务进程是否加载了至少一条格式有效的记录；`false` 表示未加载有效记录，`true` 不保证当前输入值匹配。
- **令牌验证通过但没有可用工具**通常是 scope 或后续工具条件问题。未知 scope 会被过滤掉而不是让令牌记录整体失效，所以写成 `[recordings.read](http://recordings.read)` 可能造成“已验证、但无只读工具”；必须使用 `recordings.read`、`profiles.read` 等上表所列的纯文本。之后再查管理员 `tools_enabled`、`enabled_tools`、模型类型和云端独立开关。

**管理员 / 操作员令牌生成示例**

下面的 Linux / macOS 与 Windows PowerShell 示例分别生成**不同**的管理员口令和操作员令牌；操作员只获最小只读 scope：`recordings.read`、`profiles.read`。scope 必须是**原样纯文本**，不可包含 Markdown 链接格式（例如 `[recordings.read](http://recordings.read)`）。示例会在私密终端显示令牌，请保存到部署方的 secret 管理器；不要把实际值写入仓库、终端录制、日志或工单。

**Linux / macOS（当前终端前台启动）**

```bash
# 在仓库根目录执行；每运行一次都会生成新值，不要在普通服务重启时重新生成
ADMIN_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
OPERATOR_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export ELEC_TOOL_ASSISTANT_ADMIN_TOKEN="$ADMIN_TOKEN"
export ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS="$(
  OPERATOR_TOKEN="$OPERATOR_TOKEN" .venv/bin/python -c \
  'import json, os; print(json.dumps([{"id":"field-readonly-1","token":os.environ["OPERATOR_TOKEN"],"scopes":["recordings.read","profiles.read"]}]))'
)"

export ELEC_TOOL_ASSISTANT_LOCAL_URL='http://127.0.0.1:11434/v1'
```

**Windows PowerShell（当前终端前台启动）**

```powershell
# 在仓库根目录执行；每运行一次都会生成新值，不要在普通服务重启时重新生成
$admin = (& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))").Trim()
$operator = (& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))").Trim()
$env:ELEC_TOOL_ASSISTANT_ADMIN_TOKEN = $admin
$env:OPERATOR_TOKEN = $operator
$env:ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS = (& .\.venv\Scripts\python.exe -c "import json,os; print(json.dumps([{'id':'field-readonly-1','token':os.environ['OPERATOR_TOKEN'],'scopes':['recordings.read','profiles.read']}]))").Trim()
Remove-Item Env:OPERATOR_TOKEN
# 仅检查 ID、长度与 scope，不打印 JSON 中的令牌
$rows = $env:ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS | ConvertFrom-Json
$rows | Select-Object id, @{Name='TokenLength';Expression={$_.token.Length}}, @{Name='Scopes';Expression={($_.scopes -join ',')}}
# 如需连接本地模型，可配置服务地址与默认通道；模型名称在问答窗口从发现列表选择
# $env:ELEC_TOOL_ASSISTANT_LOCAL_URL = 'http://127.0.0.1:11434/v1'
# $env:ELEC_TOOL_ASSISTANT_BACKEND = 'local'

```

上述两段均是**当前终端直接启动服务**的演示；只在另一个 PowerShell / shell 设置 `$env:` / `export` 后再从服务管理器重启，不会把这些临时变量注入到已经由它管理的进程。NSSM、任务计划程序、systemd 或 Docker 部署时，应只生成一次、把变量安全配置到对应服务 / 容器环境并重启；不要在每次重启时重生成，否则管理器仍保存旧令牌而 UI 使用新令牌。PowerShell 调用运算符是 `&`；如果复制文本中出现字面 `&amp;`（HTML 转义），应改为 `&`。`Remove-Item Env:OPERATOR_TOKEN` 只移除临时辅助变量，不会清除已经生成的 `ELEC_TOOL_ASSISTANT_OPERATOR_TOKENS` JSON。

服务启动后，可通过 `GET /api/assistant/config` 查看布尔字段 `operator_tokens_configured`，确认服务进程加载了至少一条格式有效的操作员记录；该字段不回传秘密，也不证明输入框里的这串令牌与记录匹配。PowerShell 可在另一个终端执行（端口按实际服务调整）：

```powershell
(Invoke-RestMethod 'http://127.0.0.1:8000/api/assistant/config').operator_tokens_configured
```

如使用云端，另行设置 `ELEC_TOOL_ASSISTANT_CLOUD_URL`、`ELEC_TOOL_ASSISTANT_CLOUD_MODEL` 与 `ELEC_TOOL_ASSISTANT_CLOUD_API_KEY`；云端地址须 HTTPS（localhost 测试例外）。本地模型地址只接受 loopback / 私有 IP 或显式内网域名，且本地模型请求不走系统 HTTP 代理。也可在侧栏“模型配置与附加知识（管理员）”面板调整地址、模型、超时、Temperature、token 数、RAG、敏感词和入口页面；UI 输入口令 / API Key 都不会写入浏览器存储。

**验收 / 故障定位**：`GET /api/assistant/documents` 可确认服务启动加载的本地资料目录与全文；`node tools/ui_assistant_check.cjs`（jsdom，不请求真实模型，验证会话搜索 / 分组 / 排序 / 重命名 / 删除、配置区文档浏览、响应式会话栏、安全 Markdown、SSE、截图粘贴 / 拖放与云端确认）；`pytest tests/test_assistant.py tests/test_server.py tests/test_web_ui.py -q`。截图需选择支持视觉输入的 local / cloud 模型；模型不可用时先确认本地 Ollama / vLLM 已启动、模型名和 `/v1` 基址正确；云端鉴权失败看模型服务的 Key / 权限；本地连接失败看服务端与模型同机 / 内网可达性。真实视觉模型兼容性、云端供应商请求与目标浏览器视觉效果仍需现场验收。

## 9. 生产推荐流程（台账第 7 章）

**推荐拓扑（现场实时监测）** ✅架构实录 / 🔶现场未验证

```
采集装置(二次侧 6400Hz) ──写──> data/live.csv ──tail──> csv_tail 源 ──> LiveEngine ──WebSocket──> 浏览器(局域网)
                                                            │
                                                            └──> output/result_*.csv（定时导出/归档）
```

**推荐操作序列**

1. 部署：§2.2–2.5（离线机器走 §2.4(b)/(c)），5 条验证命令全绿；
2. 口径自检：`cli.py selftest --fs <现场fs> --freq <额定> --pt <PT> --ct <CT>` 必须 44/44；
3. 数据体检：`cli.py sources --file <现场数据>`，确认编码/列映射/推算采样率；
4. 离线对账：`cli.py compute --file <现场数据> --format csv --out output/对账.csv`，与现场表计/其它系统比 U、I、P、PF、THD（差异 >1% 要查变比与口径）；
5. 实时上线：`cli.py serve`（或 systemd/NSSM 常驻 + `ELEC_TOOL_AUTOSTART=1`），源切 `csv_tail`；
6. 窗长按业务设定：电能质量类建议 voltage/current/harmonic 用 1s~5s，趋势类可用 1s 步长滑动；
7. 归档：定时导出 CSV/JSON，保留 `notes` 与缺口日志作为数据质量证据。

**不推荐**：① `uvicorn --workers N`（引擎状态在进程内存，多 worker 会各算各的）；② 直接把 `configs/default.json` 当运行配置改（应改 `runtime.json` 或用 `--config`，便于回溯出厂口径）；③ 用抽稀后的频谱做定量结论（抽稀保峰不保能量，仅用于显示）。✅（架构约束 + 实测告警文案）
